# ШІ-Репетитор — застосунок (Next.js PWA)

Код застосунку. Архітектура — `docs/02-architecture.md`, дизайн — `docs/04-design-system.md`,
зрізи — `docs/05-backlog.md`. Міграції бази — `../supabase/migrations/`.

## Структура

```
app/
  config/                 дані й конфігурація (не код): стартові налаштування сім'ї
                          (навчальний рік, клас, предмети, імена репетитора), словники перевірки імені
  public/icons/           іконки PWA (генеруються: npm run icons)
  scripts/                тестова БД, перевірка бандла на секрети, генерація іконок
  src/
    app/                  екрани й маршрути (App Router)
      (child)/            інтерфейс дитини: onboarding, today, my-tutor, about-ai, soon/[code],
                          lesson/[sessionId] (S3 — доступ лише requireParentAccess, див. нижче)
      parent/             кабінет тата
      auth/               вхід через Google, колбек, вихід
      actions/            Server Actions (кожна перевіряє роль на сервері)
    components/           UI-компоненти
      lesson/             екран уроку (пікер блоків, крок, пауза, підсумок, чат теми)
    core/registries/      реєстри ядра (ADR-017): навігація, режими, типи кроків, типи джерел
    lesson-components/    реєстр інтерактивних компонентів уроку (ADR-020): drag_sort/…
    modules/school/       навчальний модуль «Шкільна програма» (реєструється в ядрі)
    server/               лише серверний код (import "server-only"): auth, persona, db, env
      lessons/            оркестратор уроку (ADR-007): state-machine (чисті правила),
                          orchestrator (БД, включно з BUG-008/009 fixes), generate (бібліотека/
                          генерація, ADR-014), pipeline (педагогічний конвеєр plan→generate→review,
                          ADR-022, D-55), pedagogy (каталог P-P + рубрика рецензента), library
                          (read-models кабінету тата — методичний паспорт), chat (тема-чат,
                          US-8.1, BUG-010 fix), component-validator (NFR-SAFE-15), schema
    lib/                  спільна чиста логіка (валідація нікнейму/імені, формат PIN)
    i18n/uk.ts            усі тексти інтерфейсу
  prompts/                промпти ШІ-ролей (окремі файли, редагує Алекс): indexing_structure,
                          ocr_page (S1b, скановані книги), lesson_planning, lesson_generation,
                          lesson_review (ADR-022, D-55), tutor_chat, answer_evaluation
  tests/db/               RLS-тести на тимчасовому Postgres
supabase/
  migrations/             версіоновані SQL-міграції
  tests/supabase-shim.sql мінімальна імітація Supabase для локальних тестів
```

## Команди

```bash
cd app
npm ci                 # встановити залежності
cp .env.example .env.local   # і заповнити DEV-значеннями (файл у .gitignore)
npm run dev            # локальний запуск: http://localhost:3000
npm run lint           # ESLint
npm run typecheck      # TypeScript
npm test               # юніт-тести (vitest)
npm run test:db        # RLS-тести: піднімає тимчасовий PostgreSQL, застосовує міграції
npm run build          # продакшн-збірка
npm run check:bundle   # збірка з «канарковими» секретами + перевірка, що вони не потрапили в браузер
npm run build && npm run test:e2e   # Playwright: публічна/незалогінена поверхня (S0) на планшеті й телефоні
```

`npm run test:e2e` не потребує акаунтів Supabase/Google: перевіряє екрани, доступні без сесії
(вхід, offline, маніфест PWA, редіректи без сесії, відсутність секретів у HTML) у двох
в'юпортах — Lenovo Yoga 11 і Galaxy S24+ (`app/tests/e2e/`). Повні сценарії входу й PIN —
після появи акаунтів (`docs/06-test-plan.md`).

`npm run test:db` потребує локально встановленого PostgreSQL ≥ 15 (`initdb`) або змінної
`TEST_DATABASE_URL` на базу з уже застосованими міграціями.

**Пісочниці з проксі (Claude Code sandboxes тощо):** `npm run build` і `npm run test:e2e`
підвантажують `next/font/google` (Google Fonts) під час збірки, що йде через HTTPS. Якщо
мережа доступна лише через проксі (наприклад, `HTTPS_PROXY` з `/root/.ccr/`), постав
змінну середовища `NODE_USE_ENV_PROXY=1` перед цими командами, інакше збірка падає з
помилкою мережі:

```bash
NODE_USE_ENV_PROXY=1 npm run build
NODE_USE_ENV_PROXY=1 npm run build && NODE_USE_ENV_PROXY=1 npm run test:e2e
```

## Як S0 запрацює на Vercel — кроки для Алекса

Акаунти створюються за `docs/03-resources-and-costs.md`, розділ 1 (кроки «До S0»). Нічого платного.

1. **Supabase — два проєкти** `ai-tutor-dev` і `ai-tutor-prod` (docs/03, 1.4, кроки 1–4).
2. **Google Cloud — вхід через Google** (docs/03, 1.5, кроки 1–6; статус застосунку — **In production**).
   У **Authorized redirect URIs** — Callback URL із Supabase обох проєктів.
3. **Supabase → Authentication → Sign In / Providers → Google → Enable** — Client ID і Secret із кроку 2
   (docs/03, 1.4, крок 5). Для кожного проєкту.
4. **Supabase → Authentication → URL Configuration** (у кожному проєкті):
   - *Site URL*: адреса застосунку у Vercel (prod — адреса продакшну; dev — адреса preview);
   - *Redirect URLs* → **Add URL**: `https://<адреса-prod>/auth/callback`; для dev-проєкту — також
     `https://*-<ваша-команда>.vercel.app/auth/callback` (усі preview) і `http://localhost:3000/auth/callback`.
5. **Supabase → SQL Editor → New query** (у кожному проєкті): по черзі вставити вміст трьох файлів із
   `supabase/migrations/` (у порядку назв) і натиснути **Run** для кожного. Очікуваний результат — «Success».
6. **Vercel → Add New… → Project → Import** репозиторію (docs/03, 1.3). На екрані імпорту:
   **Root Directory → Edit → `app`** → Continue. Framework — Next.js (визначиться сам).
7. **Vercel → Settings → Environment Variables** (docs/03, 1.14) — для S0 потрібні лише:
   `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`,
   `ALLOWLIST_PARENT_EMAILS`, `ALLOWLIST_CHILD_EMAILS`, `PIN_PEPPER` (довгий випадковий рядок, ≥ 16
   символів). Production — prod-значення, Preview/Development — dev.
   `APP_BASE_URL` (адреса застосунку) — **лише для Production**; для Preview залиште порожнім, тоді
   застосунок бере адресу конкретного preview. Після змін — **Deployments → … → Redeploy**.
   Порада: preview-адреси Vercel за замовчуванням відкриваються лише після входу у Vercel
   (Settings → Deployment Protection) — для демо на планшеті доньки це треба врахувати.
8. Увійти своїм акаунтом → **Налаштування → PIN режиму тата** → задати PIN.
9. Перевірка входу акаунтом доньки на планшеті (R-5, docs/02 10.1) — на демо.

Зміна `PIN_PEPPER` робить збережений PIN недійсним (його треба задати знову).

## S1 «Матеріали й Мої книги» — що потрібно, щоб запрацювало

**Як це працює (коротко).** Кабінет → «Мої книги» → «Я додав — перевірити папку»: сервер читає папку
Google Drive сервісним акаунтом (ADR-003), нові PDF/EPUB одразу з'являються зі статусом «Індексується…».
Далі у фоні: завантаження → витяг тексту → сторінки (або весь файл) без текстового шару йдуть через
**OCR** (S1b, нижче) → фрагменти → ембединги OpenAI `text-embedding-3-large` → структура «розділ → тема
→ сторінки» (Claude Opus 5.5, роль `indexing_structure`). Кожен ШІ-виклик іде через маршрутизатор
(таблиця `model_routes`) і записується в `ai_calls` з вартістю; місячна сума — у `spend_months`. У
режимі бюджету нові книги (і OCR) відкладаються. Фонова робота запускається одразу після дії тата
(`after()`), продовжується, поки відкрито «Мої книги», і раз на добу — Vercel Cron
(`/api/jobs/tick?sync=1`, захищено `CRON_SECRET`).

**Кроки для Алекса**
1. Supabase → SQL Editor (у проєкті, на який дивиться застосунок) → по черзі виконати:
   `supabase/migrations/20260926100000_s1_ai_router_costs_jobs.sql`, потім
   `supabase/migrations/20260926100100_s1_materials_search.sql`. Повторний запуск безпечний.
2. Google Cloud: сервісний акаунт і API-ключ — `docs/03-resources-and-costs.md` 1.5 (кроки 7–10);
   папка — 1.6 (кроки 1–2, 5): додати e-mail сервісного акаунта в «Поділитися» з роллю «Читач».
3. Vercel → Settings → Environment Variables: `GOOGLE_SERVICE_ACCOUNT_JSON`, `GOOGLE_DRIVE_FOLDER_ID`,
   `GOOGLE_API_KEY`, `ANTHROPIC_API_KEY`, `OPENAI_API_KEY`, `CRON_SECRET` → Redeploy.

**Необов'язково:** щохвилинний тік через Supabase `pg_cron` + `pg_net` (ADR-015) — не потрібен для демо;
без нього індексація йде, поки відкрито «Мої книги», і раз на добу за Vercel Cron.

**Промпт структури книги** — `app/prompts/indexing_structure.md` (звичайний текст, можна редагувати;
плейсхолдери `{{…}}` залишити). Моделям передається лише текст книги, жодних даних доньки.

## S1b «Скановані книги (OCR)» — рішення PO D-54 — що потрібно, щоб запрацювало

**Як це працює (коротко).** PDF-сторінка без текстового шару (увесь скан або лише частина сторінок
змішаної книги) більше не відхиляється — сервер розпізнає її текст роллю `ocr_page` (Claude Sonnet 5,
задача сприйняття, а не міркування — дешевша за `indexing_structure`; докладніше — ADR-008,
docs/03 3.9б) пакетами по 6 сторінок (задача `ingest.ocr`, відновлювана після збою), «Мої книги» під
час розпізнавання показує «Розпізнається: сторінка N з M». Малий скан (≤ 20 стор. за замовчуванням,
`parent_settings.ocr_confirm_above_pages` — редагується в БД) розпізнається автоматично; більший —
показує оцінку вартості й чекає кнопки тата «🔎 Розпізнати» (нового спричинення витрат без згоди тата
немає). Розпізнаний текст іде далі звичайним конвеєром (фрагменти → ембединги → структура); повторна
індексація того самого файлу OCR вдруге не запускає. Скан, який розпізнати не вдалося (порожні або
пошкоджені сторінки), отримує статус «Скан не вдалося розпізнати» з поясненням.

**Кроки для Алекса**
1. Supabase → SQL Editor → виконати `supabase/migrations/20260929100000_s1b_ocr_scanned_books.sql`
   (після трьох попередніх файлів S0 і двох файлів S1). Повторний запуск безпечний.
2. Нових ключів/змінних Vercel не потрібно — використовує наявний `ANTHROPIC_API_KEY` (S1).

**Промпт розпізнавання** — `app/prompts/ocr_page.md` (звичайний текст, плейсхолдери `{{…}}`
залишити). Моделі передається лише зображення сторінок книги, жодних даних доньки.

## S2 «Предмет, поточна тема, прогноз-план» — що потрібно, щоб запрацювало

**Як це працює (коротко).** Кабінет → **«Предмети»** (новий пункт меню): список усіх предметів
MVP зі статусом (активовано / не активовано), наявністю готового підручника й поточною темою.
Клік відкриває предмет: якщо готового підручника ще немає (проіндексованого, типу «Підручник»,
увімкненого «в уроках» — див. «Мої книги», S1) — зрозуміле пояснення й посилання на «Мої книги»
замість спроби активації; якщо є — список тем підручника з фільтром-автопідбором (вводиш текст —
список звужується), тато обирає поточну тему й зберігає — предмет автоматично активується.
Нижче — **прогноз-план**: теми-передумови (граф залежностей, побудований під час індексації S1),
поточна тема, наступні теми за порядком підручника — усе з посиланнями на сторінки.

**Нових міграцій і змінних середовища не потрібно**: `subjects.active` і `topics.is_current`
уже існують з S0/S1; план будується детерміновано з наявних даних (без нового виклику ШІ).

**Також у цьому зрізі:** BUG-003 (потокове завантаження з Drive з лічильником байтів) виправлено;
BUG-004 (вихід з дитячого акаунта, пояснення «PIN не задано») і BUG-005 (конкретна помилка, коли
`PIN_PEPPER` не налаштовано) — виправлено за результатами демо Алекса, див. `docs/bugs/`.

## S3 «Перший урок (текст)» — що потрібно, щоб запрацювало

**Як це працює (коротко, ADR-007).** Кабінет → **«Предмети»** → предмет з поточною темою → панель
«Урок (демо)» → **«Почати урок»**. Сервер (`server/lessons/generate.ts`) шукає в бібліотеці
(`library_items`/`library_steps`, ADR-014) 2–3 готові блоки поточної теми; якщо їх бракує —
запускає педагогічний конвеєр (`server/lessons/pipeline.ts`, ADR-022, D-55, детальніше нижче) і
зберігає результат — так наступного разу генерація вже не потрібна (US-19.1, US-19.2 КП-2). Дитина
(у S3 — тато / режим тата, див. нижче) обирає один з блоків (US-16.6) і проходить кроки:
слайд-пояснення (перший — завжди «гачок», US-6.12), вибір відповіді, відкрита відповідь (оцінює
роль `answer_evaluation`) і інтерактивний крок `drag_sort` («Перетягни й співстав» — пари, групи,
порядок; перетягуванням і дотик-дотик, ADR-020). Наприкінці блоку — екран з конкретним видимим
результатом (US-6.13) і необов'язковою оцінкою «цікаво/нормально/нудно», потім наступний блок
**без повторів у межах сесії** (BUG-009 fix, `nextSessionBlock`). Оркестратор
(`server/lessons/orchestrator.ts`) — детермінована машина станів (`server/lessons/state-machine.ts`,
юніт-тести): зберігає прогрес після кожного кроку (US-6.5), пропонує підказку після 60 с
бездіяльності й автопаузу після 3 хв (налашт. — `child_profile.idle_hint_s`/`idle_pause_s`),
пропонує зміну формату після серії вгадувань/помилок (US-16.5), завершує урок лише після поточного
блоку (US-6.7 КП-2). Кнопка «Тривога» і втрата зв'язку ставлять сесію на паузу тим самим шляхом
(`pause_reason`); «Продовжити» відкриває той самий крок, а після паузи ≥ 24 год — спершу коротке
нагадування (BUG-008 fix). Відповідь дана під час обриву мережі не губиться — клієнтська черга в
IndexedDB надсилає її автоматично, щойно зв'язок повернувся (BUG-007 fix,
`components/lesson/offlineQueue.ts`). Чат теми (US-8.1, 8.2) відповідає лише за фрагментами
підручника теми, з посиланням на сторінку; підручник завжди має пріоритет над додатковою книгою,
якщо вони суперечать (BUG-010 fix).

**Педагогічний конвеєр (ADR-022, D-55) — `server/lessons/pipeline.ts`.** Один новий блок = три
ролі підряд: **`lesson_planning`** (Claude Opus 5.5) — методичний план (мета, «гачок», видимий
результат, ≥ 2 прийоми з каталогу P-P — `server/lessons/pedagogy.ts`, типові помилки, тон);
**`lesson_generation`** (той самий провайдер) — сценарій за планом; **`lesson_review`** (**OpenAI —
обов'язково інший провайдер**, `server/ai/providers/openai.ts`, Responses API з JSON Schema
strict-режимом, без офіційного SDK) — незалежна рецензія за рубрикою з 9 критеріїв (0–2 бали
кожен). `revise` → нова спроба генерації з зауваженнями рецензента, до 2 доопрацювань; якщо жодна
не пройшла — блок зберігається як `needs_review` і **ніколи не показується дитині** (той самий
фільтр `status = 'active'`, який бібліотека вже мала), тату — подія в центр сповіщень. Рецензія
**не вимикається режимом бюджету** (NFR-COST-12). Кожен блок отримує «методичний паспорт»
(`library_items.pedagogy`) і історію рецензій (`library_item_reviews`) — видно в кабінеті тата:
сторінка предмета → «Бібліотека блоків теми» → картка `/parent/library/[id]`.

**Безпека інтерактивних компонентів (NFR-SAFE-15, ADR-020):** модель ніколи не повертає
HTML/JS/SVG/URL — лише `component` (ключ з реєстру `src/lesson-components/`) + `props` за
Zod-схемою компонента. `server/lessons/component-validator.ts` перевіряє схему, семантику
(еталон узгоджений з даними) і безпеку тексту (`<script>`, розмітка, посилання) до збереження;
будь-яка з цих помилок → крок автоматично замінюється вправою-вибором/відкритою відповіддю, подія
пишеться в консоль сервера (технічний журнал), урок не блокується — покрито юніт-тестами
(`component-validator.test.ts`, набір «зламаних» описів).

**S3-обмеження (навмисне, до S4):** урок відкривається лише через `requireParentAccess()` — тобто
з акаунта тата або з режиму тата на планшеті (позначка «🔒 Режим тата» на екрані уроку) — доки
правила безпеки розмови (NFR-SAFE-1…14) не перевірено в S4. Дитина самостійно урок ще не запускає.

**Спрощення в межах документів (записати сюди фактичні висновки після демо):** альтернативне
пояснення при неправильній відповіді (US-6.3 КП-1, US-19.3 КП-2) у цьому зрізі — це вже наявне
пояснення кроку (`explanationUk`, збережене разом з блоком), а не окремий згенерований
`alt_explanation`-елемент бібліотеки чи повна заміна кроку; «позначення теми на повторення» після
двох невдалих спроб поспіль (US-6.3 КП-2) поки що не пише в карту знань — таблиця `knowledge_state`
з'являється в S6 (Діагностика і карта знань), а S3 лише рухає сценарій далі без відчуття провалу.
Обидва пункти — кандидати на уточнення в S6/S8, не баг. **US-6.14** (репетитор спирається на
попередні успіхи/труднощі дитини) чекає на профіль (S16) — план (`toneNotesUk`) уже готовий
прийняти цей контекст без зміни структури промпту, коли профіль з'явиться; до S16 блок працює без
персоналізації успіхів, як і прямо дозволяє backlog S3.

**Нових акаунтів не потрібно** — S3 повністю використовує маршрутизатор, Drive-індексацію і ключі з
S1 (`ANTHROPIC_API_KEY`, `OPENAI_API_KEY` — обидва мали вже бути задані з S1; `lesson_review` тепер
теж використовує `OPENAI_API_KEY`, як і ембеддинги). Дві нові міграції, у цьому порядку:
`supabase/migrations/20260928100000_s3_lesson_orchestrator.sql`, потім
`supabase/migrations/20260930100000_s3b_pedagogical_pipeline.sql` (виконати в Supabase SQL Editor
після всіх попередніх; повторний запуск безпечний).

**Промпти** — `app/prompts/lesson_planning.md`, `app/prompts/lesson_generation.md`,
`app/prompts/lesson_review.md`, `app/prompts/tutor_chat.md`, `app/prompts/answer_evaluation.md`
(звичайний текст, редагує Алекс; плейсхолдери `{{…}}` не чіпати). Жодного з них не бачить справжнє
ім'я чи e-mail дитини (NFR-SAFE-8) — планування й генерація уроку не отримують навіть нікнейму (він
підставляється лише під час показу), чат теми отримує нікнейм і ім'я репетитора (докладно —
`docs/02-architecture.md` 5.4). Рецензент (`lesson_review.md`) отримує лише сценарій блоку, план і
фрагменти підручника — так само без нікнейму й імені.
