## 1. Чекліст для Алекса: акаунти, ключі, куди їх вписати (AR-15)

### 1.0. Загальні правила
1. **Паролі** від усіх акаунтів — у менеджер паролів (Google Password Manager підходить). Увімкніть двофакторну автентифікацію скрізь, де пропонують.
2. **Ключі [секрет]** ви вносите **самі** у Vercel (розд. 1.14). Розробнику ключі **не надсилаються** — ні в чат Claude, ні листом. Для локальної розробки розробник дасть файл-шаблон `.env.example`; ви копіюєте його як `.env.local` у папку проєкту й вставляєте **dev-ключі** (з малими лімітами).
3. Для кожного ШІ-провайдера робіть **два ключі**: `ai-tutor-dev` (розробка, preview) і `ai-tutor-prod` (для доньки).
4. **Автопоповнення рахунку — вимкнено** скрізь. Це «запобіжник»: навіть при помилці в коді провайдер не спише більше, ніж поклали.
5. Кроки з **[$]** — лише на суми, погоджені 2026-09-25 (розд. 5); будь-яка інша сума — спершу нове підтвердження.

### 1.3. Vercel (хостинг застосунку) — безкоштовно (Hobby)

4. Далі тут ви вноситимете ключі: **Project → Settings → Environment Variables** (розд. 1.14).

### 1.4. Supabase (база й сховище) — Free, пізніше Pro $25 [$]
1. **supabase.com** → **Start your project** → **Continue with GitHub**.
2. Створіть **організацію** `ai-tutor-prod` (тариф Free) → **New project**: назва `ai-tutor-prod`, регіон **Central EU (Frankfurt)**, пароль бази — **згенеруйте** і збережіть у менеджер паролів **[секрет]**.
3. Створіть **другу організацію** `ai-tutor-dev` (Free) з проєктом `ai-tutor-dev` (той самий регіон) — для тестів. Окрема організація потрібна, щоб тестовий проєкт лишався безкоштовним, коли продакшн перейде на Pro.
4. У кожному проєкті: **Project Settings → API** — там три значення: `Project URL`, `anon public` key, `service_role` key **[секрет]**. Їх внесете у Vercel (розд. 1.14): prod-значення — у Production, dev — у Preview/Development.
5. Після кроку 1.5 (Google): **Authentication → Sign In / Providers → Google → Enable** → вставте **Client ID** і **Client Secret** → **Save**. Скопіюйте звідти **Callback URL** — він знадобиться в 1.5.

### 1.5. Google Cloud (вхід через Google, доступ до Drive, Gemini) — безкоштовно; білінг для Gemini [$]
**А. Проєкт і вхід через Google**
1. **console.cloud.google.com** → увійдіть **своїм** Google-акаунтом → вгорі **Select a project → New Project** → назва `ai-tutor` → **Create**.
2. Меню **APIs & Services → Library** → знайдіть **Google Drive API** → **Enable**.
3. Меню **Google Auth Platform** (або **APIs & Services → OAuth consent screen**) → **Get started**:
   - **App name:** `ШІ-Репетитор`; **User support email:** ваш e-mail;
   - **Audience:** **External**;
   - **Contact information:** ваш e-mail → **Create**.
4. **Data Access → Add or remove scopes** → позначте `openid`, `.../auth/userinfo.email`, `.../auth/userinfo.profile`, `.../auth/drive.file` → **Update → Save**. (Усі чотири — «не чутливі»; перевірка Google не потрібна.)
5. **Audience → Publish app → Confirm** — статус має стати **In production**. *Навіщо:* у статусі «Testing» дозвіл на Drive зникає кожні 7 днів, і архів не працюватиме.
6. **Clients → Create client** → тип **Web application** → назва `ai-tutor-web` →

**Б. Сервісний акаунт (читання папки з підручниками)**

### 1.6. Папка Google Drive з підручниками (R-8) [!]
1. Відкрийте папку в **drive.google.com** → **Поділитися (Share)**.
2. У полі «Додати людей» вставте **e-mail сервісного акаунта** (1.5, крок 8) → роль **Читач (Viewer)** → зніміть галочку «Сповістити» → **Надіслати**.
3. **Якомога раніше (рекомендація):** у блоці **«Загальний доступ»** змініть «Усі, хто має посилання» з **Редактор** на **Читач**.
4. **До S17 і до потрапляння в Drive будь-яких даних доньки — обов'язково:** «Загальний доступ» → **Обмежений доступ** (лише додані люди). Застосунок сам покаже попередження, поки папка відкрита, і **не створить архів** у відкритій папці.
5. **ID папки [секрет]:** відкрийте папку — в адресному рядку після `folders/` йде довгий набір символів. Це і є ID → у `GOOGLE_DRIVE_FOLDER_ID` (1.14). Посилання на папку нікуди не пересилайте.
6. **Папка архіву (до S17):** у кабінеті застосунку натисніть **«Підключити архів Google Drive»** → оберіть свій акаунт → **Дозволити** (застосунок бачитиме лише файли, які сам створить). Застосунок створить приватну папку «ШІ-Репетитор — Архів» і покаже її ID → внесіть у `GOOGLE_DRIVE_ARCHIVE_FOLDER_ID` (1.14).
7. **Місце на Drive:** архів займатиме ≈ 0,5 ГБ на місяць (≈ 3–10 ГБ за рік). У вас підписка Google One — місця достатньо (рішення 2026-09-25, розд. 5). Застосунок усе одно перевіряє вільне місце перед архівацією і стискає аудіо в архіві.

### 3.2а. Вартість педагогічного конвеєра (D-55, ADR-022): планування + рецензія

Замінює прямий виклик `lesson_generation` на 3–5 кроків (розд. 7.7 `docs/02`): `lesson_planning` → `lesson_generation` → `lesson_review` (незалежний провайдер) → до 2 ітерацій доопрацювання. Виконується **один раз на блок**, при генерації для бібліотеки — вартість повторів (проходжень із бібліотеки) не змінюється.

| Крок | Модель | Оцінка виклику | Вартість |
|---|---|---|---|
| `lesson_planning` (мета, міскончепції, прийоми, «гачок», прогрес, тон) | Claude Opus 5.5 ($4/$20 за 1M) | ≈ 8K вхід + ≈ 1,5K вихід | ≈ **$0,06** |
| `lesson_generation` (сценарій за планом) | Claude Opus 5.5 | ≈ 10K вхід + ≈ 5K вихід (як і раніше, П-3) | ≈ **$0,14** |
| `lesson_review` (рубрика: методика/факти/вік/зацікавленість/тон/різноманітність/безпека/ПД) | GPT-5.6 Sol (промо $4/$20 за 1M) | ≈ 12K вхід + ≈ 1K вихід | ≈ **$0,07** |
| **Разом за блок (без доопрацювання)** | | | ≈ **$0,27** (було $0,14) |
| Очікувана 1 ітерація доопрацювання (припущення ≈ 30 % блоків, `revise`) | generation + review ще раз | | + 0,30 × ($0,14+$0,07) ≈ **$0,06** |
| **Разом за блок, очікувано** | | | ≈ **$0,33** (**+$0,19/блок**, +140 %) |

| Урок | Було (новий) | Стало (новий, з конвеєром) | Різниця | Повтор з бібліотеки |
|---|---|---|---|---|
| 30 хв (4 блоки) | $2,74 | **≈ $3,50** | +$0,76 (+28 %) | $1,38 (без змін) |
| 45 хв (6 блоків) | $4,07 | **≈ $5,21** | +$1,14 (+28 %) | $2,03 (без змін) |

**Вплив на «Економ» за місяць** (≈ 11 нових 30-хв уроків/міс, 3.5): +11 × $0,76 ≈ **+$8,4/міс**. ШІ-витрати «Економу» (розд. 3.5) ≈ $64 → **≈ $72–73/міс** — усе ще в межах ліміту $100 (запас ≈ $27–28 замість $36). Разом на місяць (з інфраструктурою) ≈ $111 → **≈ $119–120**.

**Бюджетний режим:** рецензія не вимикається (безпека/якість — поза економією), але переходить на дешевшого рецензента (Gemini 3.8 Flash, спрощена рубрика) — вартість рецензії в режимі бюджету ≈ $0,01–0,02 замість $0,07; планування в режимі бюджету спрощується/пропускається так само, як і зараз генерація (US-11.5 КП-6).

*Припущення:* частка блоків, що йдуть на доопрацювання (`revise`) ≈ 30 % — оцінка до перших реальних рецензій; уточнити після 10–15 згенерованих блоків (запис у `docs/STATUS.md`, як і AR-R23). Ціни моделей — ті самі джерела, що в розд. 6.

### 3.2б. Вартість фонового прогрівання бібліотеки (D-76, ADR-023)

Прогрів **не** додає нового виду виклику — це той самий конвеєр з розд. 3.2а, лише запущений раніше (за сигналом «тема позначена поточною», D-65) і **лише для першого блока теми** (розд. 7.7a `docs/02`), а не для всього уроку відразу.

| Сценарій | Розрахунок | Вартість |
|---|---|---|
| Прогрів однієї теми (1 блок, з очікуваною доопрацею ≈30%) | той самий блок, що в 3.2а | ≈ **$0,33** (як і «за блок» вище) |
| Тато позначає **5 тем** предмета поточними одночасно | 5 × $0,33 | ≈ **$1,65** одноразово |
| Тато позначає **весь підручник** (≈ 25–35 тем 6 класу) поточними одночасно — **найгірший випадок** | 30 × $0,33 (лише перші блоки; наступні блоки уроку — при реальному проходженні, як і зараз) | ≈ **$8–12** одноразово, розтягнуто в часі лімітом паралельності (розд. 7.7a п. 4: 2 одночасно) і денним м'яким лімітом $5/день (≈ 2 дні на весь підручник) |
| Порівняно: прогрів **усього уроку** (≈4 блоки) на тему, а не лише першого | 4 × $0,33 | ≈ $1,3/тему — **у 4 рази дорожче**, тому свідомо не робимо (7.7a п. 2) |

**Висновок:** навіть найгірший випадок (тато одразу позначає весь підручник) — одноразово ≈ $8–12, розтягнуто на кілька днів денним лімітом $5 і чергою з 2 паралельних warm-конвеєрів — непомітно на фоні місячного ліміту ШІ $100 і не створює різкого стрибка витрат за один день. Це й було головним занепокоєнням PO при формулюванні D-76.

### 3.2в. Вартість швидкого інтерактивного шару (D-77/D-78, ADR-023)

Роль `step_reinforcement` (пояснення помилки + вправа на закріплення, US-6.15/D-74) і «поясни задачу №N» (US-8.7/US-2.8, D-78) — **один швидкий виклик**, того самого порядку вартості, що вже закладений для `answer_evaluation`/`tutor_chat` (розд. 3.1, П-5): одиниці центів за виклик.

| Виклик | Оцінка | Вартість |
|---|---|---|
| `step_reinforcement` (Sonnet 5, ~4K вхід + ~1K вихід — контекст кроку, еталон, тип помилки) | за прикладом `answer_evaluation`/П-5 | ≈ **$0,01–0,02** за виклик |
| «Поясни задачу №N» (retrieval — $0; один виклик Sonnet 5 поверх знайденого фрагмента) | retrieval безкоштовний (уже проіндексовано, S1/S1b); генерація — як `tutor_chat` | ≈ **$0,01–0,02** за репліку |
| Фонова асинхронна «harvest»-рецензія вибраних прикладів на `alt_explanation` (не в шляху дитини) | рідко (вибіркові повторювані випадки), той самий конвеєр, що й 3.2а, але без впливу на латентність дитини | входить у загальний бюджет генерації бібліотеки, окремо не рахуємо |

**Вплив на місячний кошторис (розд. 3.5):** за оцінкою ≈ 5–10 випадків «неправильна відповідь → закріплення» за середній урок і ≈ 22 навчальні дні — додатково ≈ **$1–3/міс** у «Економі» — вже в межах запасу ліміту $100 (розд. 0), не потребує окремого перегляду сценаріїв.

### 3.5. Сценарії на місяць: «1 дитина, будні, X хв живого голосу на день»

Моделі в усіх сценаріях однакові (якість — P-Q); різниця — в обсязі занять.

> **Стартовий сценарій MVP — «Економ»** (рішення Алекса 2026-09-25). «Базовий» і «Комфорт» — варіанти на потім: переходимо лише після тестування (≥ 2 тижні фактичних витрат) і окремого підтвердження **[$]**. Застосунок не обмежує кількість уроків (P-T) — «Економ» означає планування й очікуваний обсяг, а захист бюджету забезпечує ліміт $100 (розд. 4).

> **Рішення 2026-09-25:** ліміт $100 — **лише для ШІ-витрат**; підписки Supabase Pro ($25) і ElevenLabs Creator ($22) — фіксована інфраструктура поза лімітом. | Голос «ШІ-друга» 20 → 10 хв | −$30 | **Прийнято 2026-09-25** — уже враховано в сценаріях вище |

| Переозвучити всю бібліотеку одразу (кнопка тата, не за замовчуванням) **[$]** | ≈ 8 000 символів × кількість уроків (рік «Економу» ≈ 110 уроків) | ≈ $0,80 за урок; до ≈ **$88** за річну бібліотеку |
| Режим «старі уроки — старим голосом» (`keep_old`) | переозвучення не виконується | **$0** |
| Аватар-картинка: сховище | ≤ 5 файлів × ≤ 150 КБ | **$0** (у межах Supabase Pro) |
| Аватар: перевірка | лише валідація формату/розміру й стиснення на планшеті та сервері; автоматичної модерації в MVP немає (рішення PO 2026-09-25, ADR-019); зображення не йде в жодні моделі й сервіси | **$0** |
| Анімація аватара (CSS/Canvas на планшеті) | без зовнішніх сервісів | **$0** |
| **Разом для MVP** | | **≈ $0/міс** + переозвучення лише після зміни голосу |

*Припущення:* ціна переозвучення — як у звичайної озвучки Multilingual ($0,10 / 1 000 символів; на Flash — удвічі менше); ціна докупівлі кредитів понад пакет Creator звіряється на S12 (AR-R5). Часті перемикання голосу не множать витрати без меж: кожен урок озвучується кожним голосом **лише раз**, старі файли зберігаються (повернення до попереднього голосу — $0).

### 3.9а. Інтерактивні й анімовані уроки (рішення PO 2026-09-25; `docs/02` розд. 14.3, ADR-020)

**Статус: прийнято** — у MVP повний мінімум (3 компоненти; «шкала часу» для історії — варіант перетягування карток). Витрати нижче — прийняті й входять у кошторис «Економ» (≈ +$1/міс у межах ліміту ШІ $100).

ШІ генерує не код, а короткі дані для наших готових компонентів (числова пряма, перетягування карток, покрокове пояснення). Тому додаткові витрати — лише на кілька сотень токенів у генерації нового уроку.

| Що | Розрахунок | Вартість |
|---|---|---|
| Генерація нового уроку з компонентами | каталог компонентів у промпті ≈ +1–2K вхідних токенів на блок (кешується) + дані компонентів ≈ +0,5–1K вихідних (Opus 5.5: $4 / $20 за 1M) | ≈ **+$0,01–0,03 на блок**, ≈ +$0,05–0,1 на новий 30-хв урок |
| «Економ» за місяць (≈ 11 нових уроків) | 44 блоки × ≈ $0,02 | ≈ **+$1/міс** |
| Повтор з бібліотеки | дані збережено, генерації немає | **$0** |
| Оцінювання інтерактивних відповідей | кодом компонента, без ШІ | **$0** (невелика економія на `answer_evaluation`) |
| Сервіси й бібліотеки | компоненти — частина застосунку (`dnd-kit`, `motion`, KaTeX — безкоштовні) | **$0** |
| Розробка MVP-мінімуму (прийнято) | формат + реєстр + `number_line`, `drag_sort` (+ варіант «шкала часу»), `step_reveal` | ≈ **4–5 днів розробника** + ≈ 0,5 дня дизайнера |

*Припущення:* розмір даних компонентів — оцінка для 1–2 інтерактивних кроків на блок; точніше — після перших згенерованих уроків (облік у `ai_calls`).

### 3.9б. Скановані книги — OCR (рішення PO D-54, 2026-09-26; зріз S1b)

**Модель:** роль `ocr_page` — **Claude Sonnet 5** (не Opus 5.5, на відміну від `indexing_structure`/`lesson_generation`). Обґрунтування: розпізнавання друкованого тексту зі сторінки — задача сприйняття, а не міркування; якість розпізнавання в Claude мало залежить від рівня моделі, а ціна — залежить прямо пропорційно кількості сторінок (до 600 сторінок підручника, на відміну від одного виклику `indexing_structure`). Sonnet 5 удвічі дешевший за Opus 5.5 при порівнянній якості розпізнавання друкованого українського тексту. Формат входу — PDF-сторінки (пакетами по 6) як документ (`content: [{type: "document", source: {type: "base64", ...}}, ...]`) — офіційний Anthropic SDK, без Files API (пакети невеликі, до кількох МБ); ліміти Claude API — 32 МБ і до 600 сторінок на запит (моделі з контекстом 1M), що з великим запасом покриває наш пакет із 6 сторінок. Резерв (GPT-5.6 Sol) поки не додано — та сама причина, що й для `indexing_structure` (docs/STATUS.md): точний ідентифікатор моделі не звірено в консолі OpenAI.

**Оцінка вартості на підручник 200 сторінок (повний скан):**

| Крок | Розрахунок | Вартість |
|---|---|---|
| OCR 200 сторінок (Sonnet 5: $2/$10 за 1M) | ≈ 1600 вх. + 700 вих. токенів/сторінку (сторінка-зображення + розпізнаний текст) × 200 | **≈ $2,0** |
| Подальша структура (`indexing_structure`, Opus 5.5, як і для текстового PDF) | той самий крок, що й у S1 (ADR-008) | ≈ $1–1,5 |
| **Разом, скан 200 стор. → готовий підручник** | | **≈ $3–3,5** (разово, як і звичайна індексація) |

Для порівняння: текстовий PDF (S1) того самого обсягу коштує ≈ $1–1,5 (лише структура, ембединги — центи) — скан дорожчий приблизно **удвічі-втричі**, але лишається разовою витратою на книгу (ADR-008), а не на урок. Малі скани (за замовчуванням ≤ 20 стор., `parent_settings.ocr_confirm_above_pages`) розпізнаються автоматично без запитання; підручник на 200+ сторінок завжди перевищує поріг → тато бачить оцінку й тисне «Розпізнати» до початку витрат (D-54).

*Припущення:* 1600/700 токенів на сторінку — оцінка з документації Anthropic для сторінки формату A4 із середньою щільністю тексту (може відрізнятися для дуже щільних/розріджених сторінок); звірити на реальному скані під час демо S1b і записати фактичну вартість у `docs/STATUS.md` (як і для S1 текстових підручників).
