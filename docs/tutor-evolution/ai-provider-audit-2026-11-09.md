## Висновок і межі доказів

Розподіл ролей не відповідає цьому наміру. Основні початкові маршрути дитячого текстового діалогу ведуть у Claude. Реалізованих викликів Gemini API немає. Три ключі у hosting settings не означають три інтегровані сервіси.

Production-доказ: наданий власником запис `lesson_explanation_failed` містить `provider: anthropic, status: 401`; після заміни простроченого ключа власник підтвердив відновлення пояснень. Це підтверджує провайдера конкретного невдалого запиту, але не точний ID моделі та не всі інші production-маршрути.

У поточному cloud runtime доступні public Supabase URL/anon key, немає service-role доступу чи management tools Vercel/Supabase. Тому live `model_routes`, історію `ai_calls`, фактичні витрати та всі Vercel secrets не прочитано. Нижче чітко відокремлені реалізовані можливості й початкові записи міграцій. Точні назви моделей у міграціях — історичні рядки конфігурації, не перевірена сьогодні рекомендація чи підтверджена доступність моделей у API.

## Реальна схема викликів

Функція застосунку → роль → `model_routes` у Supabase → бюджетна політика → провайдер/модель → запис `ai_calls`.

Це маршрутизатор у TypeScript, а не постійно запущений Claude-агент, який сам керує іншими ШІ. `.claude/agents` описує ролі команди розробки; це не runtime-агенти репетитора. Claude Code у браузері й Claude API всередині застосунку — різні системи.

## Чому це стало можливим

1. `ai/store.ts:loadRoute` завантажує фактичну модель з БД, кеш 30 секунд. Заміна промпту або поява ключа OpenAI не змінює цей рядок.
2. Seed-функції використовують `on conflict (family_id, role) do nothing`. Навіть зміна default у новому коді сама не змінить існуючий маршрут сім’ї.
3. Escalation і fallback різні: escalation обирається за явним `ctx.escalate`; помилка 401 сама не включає Opus. Для `tutor_chat` початковий seed має лише escalation. Якщо live рядок не змінений, резерв на OpenAI відсутній.
4. Router пробує fallback після ProviderError/AiNotConfiguredError за наявності fallback-полів. Сам по собі `retryable=false` не забороняє цей перехід. Для Gemini немає жодного runtime adapter — запис резерву в БД не створює робочого резерву.
5. Дашборд «Бюджет і моделі» показує витрати/лічильники, але не редактор фактичних маршрутів. Батько не бачить явної карти «функція → основний → резерв → модель».

## Gemini: описано більше, ніж реалізовано

`GOOGLE_GENERATIVE_AI_API_KEY` є в `.env.example`, але виконуваний код його не читає. `GOOGLE_API_KEY` у `server/env.ts` використовується для Google Drive, а не Gemini. Google Drive, Google login і Gemini — окремі інтеграції.

У `ai/router.ts` реалізовано structured adapters OpenAI/Anthropic, embeddings OpenAI, vision Anthropic, TTS/STT OpenAI. Gemini adapter, виклики Generative Language/Vertex AI, grounding/web-search інструменти, image/video generation відсутні. Текст у документації про «підключено/використовується» не підтверджує реалізацію; зокрема розділ 7.4a `02-architecture.md` описує Gemini як підключений для фото/резерву, чого код не підтверджує.

Gemini як «база знань» слід конкретизувати: база фактів/уроків/джерел зберігається у Supabase/Storage; Gemini може бути моделлю для дослідження й підготовки матеріалів. Власні знання моделі не рівнозначні перевіреному пошуку з посиланнями. Поточні відповіді використовують переданий матеріал і знання вибраної моделі, без автоматичного зовнішнього пошуку.

Поточний план `tutor-evolution/developer-team.md` призначає Gemini внутрішній команді дорослих і прямо відокремлює це від дитячого runtime. Перед новою інтеграцією слід узгодити цей старий дизайн з нинішнім наміром власника та перевірити актуальні умови обраного Google API; аудит не перевіряв їх повторно онлайн.

## Якість пояснень не визначається самим провайдером

Підтверджений окремий фактор: `prompts/explain_step.md` просить лише 2–4 речення, а `explainSchema` у `chat.ts` обмежує відповідь 900 символами. Кнопка передає `stepText`, не повний контекст уроку й діалогу. Голосовий чат має окремий багатший контекст. Це може обмежувати пояснення навіть після переходу на GPT; довша відповідь може не пройти схему. Частоту таких відмов у production не виміряно.

Немає доказів, що одна модель краща для всіх предметів. Для вибору потрібне однакове завдання/контекст/рівень дитини й сліпе порівняння. Власник 9 листопада уточнив пріоритет GPT або Gemini для підготовки пояснень. Рекомендований перший крок: GPT для живого діалогу й пояснень; окремо перевірити Gemini для підготовки контенту.

Мінімальна рубрика порівняння (це план, викликів моделей не виконано):

| Приклад | Критерій |
|---|---|
| `2,17 + x = 3,42` | Коректний метод, десяткова кома; контрольне значення x=1,25. Якщо просять підказку — не видавати всю відповідь відразу |
| `9,1 : x = 2,6` | Не переплутати невідомий дільник; контрольне x=3,5; перевірка підстановкою |
| «Не зрозуміла, чому віднімаємо» | Інший приклад/аналогія, пояснення рівності, а не повтор попереднього тексту |
| «Поясни №357» без умови | Використати точний lesson resolver; за неоднозначності уточнити, не вигадати умову |
| «Розкажи більше про вірування Давнього Сходу» | Вікова адаптація, коректне доповнення знань, розрізнення джерела/загального пояснення, без вигаданих посилань |

Оцінювати правильність, зрозумілість для 6 класу, природність українського озвучення, роботу з уточненнями, затримку першої репліки/повної відповіді та вартість. Не запускати важкого Claude-review на кожній дитячій репліці — це збільшить очікування й витрати.

3. Переробити контракт пояснення: контекст вправи/джерело, педагогічні кроки й межі відповіді. Порівняти на рубриці вище до масової заміни. Додати видиму батькові карту провайдерів і журнал фактичних моделей без технічного шуму дитині.
4. Claude залишити для явно визначених аналітичних задач/перевірки підготовленого контенту. Управління прогресом, доступом і навчальним планом лишається детермінованим кодом. Нового «головного автономного агента» зараз не створено.
5. Gemini додавати окремими адаптерами: спочатку підготовка матеріалів для дорослого з джерелами, потім ілюстрації, потім короткі відеовставки як додатковий матеріал. Для відео потрібні async job/status/retry/ліміт витрат/зберігання/перегляд батьком; наявність текстового Gemini ключа не створює відеопайплайн. Не замінювати готові уроки та Pictory-відео.

## Додаткові знахідки

- `ai_calls` містить model/provider/status/fallback/latency/cost, але це облік застосунку, не рахунок провайдера. Невідома ціна записується як 0 з логом; невдалі платні запити можуть не мати реальної usage у записі. Поточні рахунки цим аудитом не звірено.
- При одночасній відмові обох шарів модерації код працює fail-open, позначає `layersUnavailable` для події. Це наявна політика, не доказ відсутності перевірок і не внесена цим аудитом зміна.
- Причину прострочення ключа виправив власник. До цього PR126 усунув приховування збою під виглядом готового пояснення. Це окремі виправлення від правильного призначення моделей.

Аудит не змінює runtime-код, маршрути, промпти, бюджети, уроки чи секрети. Платних AI-викликів не виконано.

Перевірка: 73 наявні unit tests (router, transcription router, provider adapters, voice service) пройшли; це перевірки з mocks, не підтвердження live маршрутів/якості моделей. Пошук по виконуваному коду не виявив Gemini/Vertex API-викликів. `git diff --check` пройшов.
