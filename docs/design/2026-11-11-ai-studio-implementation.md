# Майстерня ШІ — перший робочий зріз

Власник 2026-11-11 доручив реалізацію і додав розширені уроки до наявної теми. Автор: Codex. Це доповнює аудит 2026-11-10; підтвердження production уже надане власником раніше.

## Сценарії

- Новий урок/мінікурс з ідеї, тексту/файлу або вибраної книги бібліотеки. Підручник не обов’язковий. Перший зріз — 1–6 повних уроків; великі програми створюються частинами.
- Розширений урок за предметом/темою: точний основний урок із п’яти наявних readers + текстовий пошук у family-scoped матеріалах предмета/вибраної книги, відомі сторінки й межі покриття. Доповнення зі знань ШІ позначаються окремо від наданих джерел. Відсутність індексу — явна примітка, не вигадані джерела.
- План → редагування/погодження татом → автор → дизайнер навчальних схем → незалежний review-pass → preview → явна публікація. Невдала рецензія блокує publish. Повторна підготовка — лише за командою тата, в межах бюджету.
- Опубліковане розширення доступне з картки базового уроку та навігації читача. Усередині розширення є повернення до базового уроку. Вихід зупиняє озвучення через наявний audio lifecycle; базові IDs/progress не змінюються.

## Реалізація

Нові background types `studio.step`, один короткий етап на claim, checkpoint після кожного виклику, enqueue dedupe. Приватний project document з revision/state/source snapshot міститься в payload окремого `jobs` рядка `studio.project` зі status=done (не виконується worker). Це дозволяє атомарний compare-and-swap по revision без не застосованої SQL-міграції; jobs уже має parent-only RLS. Public child views отримують лише whitelist metadata опублікованих проєктів, не raw payload/ключі відповідей. Тип studio.project є довгостроковим записом, його не можна включати в майбутній загальний cleanup тимчасових jobs. Наступна масштабна версія може перенести документи в окремі versioned tables через контрольовану міграцію.

Кожний AI-stage має окремий role/model у чинному router, облік фактичних витрат і загальний hard budget stop. У проєкту також cap: перед платним викликом резервується консервативна верхня межа за configured price/input/output. Резерв не повертається при невизначеному збої API, щоб повтори не обходили cap. Суми actual і reserved показані окремо. Router retries/fallback для цих нових ролей не дозволяються без врахованого резерву. Моделі — OpenAI GPT-5.4; інші провайдери не підміняються мовчки. Нових paid calls під час тестів не виконувати.

Публікація через перевірений universal chapter/V3 contract, з окремим package namespace на проєкт, новими темами для розширень, SVG-схемами з typed primitives, приватними quiz keys. Під час запису нові lesson rows неактивні; після повного запису, перевірки медіа й збереження зв’язку — активація. Не викликає retired broad cleanup, не деактивує старі пакети. Новий курс створюється як subjects.kind=course, а не як нова хардкоджена схема. Published content не перегенеровується поверх пройденого; повторна версія потребуватиме окремої чернетки.

Ілюстрації першого зрізу — фактичні SVG навчальні схеми (послідовність, порівняння, таймлайн, просте креслення з розмірами), без довільного SVG/HTML від моделі. Текст XML-escape, жодних script/URL/foreignObject; модель генерує тільки структуровані дані. Це не фотогенерація Gemini/Pictory. Код у програмуванні відображається як екранований code block, не виконується. Не заявляти тестування Roblox Studio на Linux. Практичні інструкції містять межі та дії дорослого; reviewer перевіряє фактаж/розміри/вік і узгодженість схем.

## Приймання

Тато створює новий урок без книги; бачить план/джерела/обмеження/ціну; перезавантаження сторінки не губить stage; повторний click не дублює job; більший курс працює поетапно; failed stage дає безпечний код без секретів; review fail не публікується; зміни після запуску не приймаються за старою revision. Стороння сім’я/дитина не читають draft і не запускають генерацію. Опублікований курс має всі кроки/вправи/схеми, text+voice і стандартну навігацію. Розширення не підміняє базовий урок і дозволяє одразу повернутися до нього.

## Реалізовані деталі та межі

`/parent/studio` — проєкти; `/parent/studio/new` — ідея/курс або розширення; `/parent/studio/[id]` — план, фінанси, джерела, етапи, повний preview, доопрацювання обраного уроку, пауза/продовження й publish/withdraw. У каталозі предмета є «Розширити з ШІ» та посилання на вже створені розширення. Курсам доступний готовий каталог замість старих forecast/warmup forms. На дитячій картці базового уроку — розширення; у shared lesson header — відкрити/закрити й повернутися. Розширені теми не дублюють основний список дитини.

Шляхи файлів користувач не передає. Невеликий TXT/MD/текстовий PDF (до 3 МБ, до 80 PDF-сторінок і 40 000 текстових символів) обробляється окремим parent-only multipart API: не впирається в default 1MB Server Actions. PDF без текстового шару відхиляється до генерації, навіть коли рядки «сторінка N» самі перевищили б поріг. Великі PDF/EPUB — чинний uploader бібліотеки, потім вибір матеріалу/сторінок. Пошук — наявний SQL text search, без платного embedding на кожний клік. До 31 явно вибраної сторінки, відомі фактичні chunks і назви книг; завеликий обсяг відхиляється, не обрізається. Джерела зберігаються як snapshot цієї чернетки, не перечитуються непомітно після авторської роботи. Внутрішні subject/topic/material IDs та дубль sourceText не надсилаються моделі; назва предмета передається явно.

Фоновий worker має окремий CAS-claim тільки `studio.step` цього проєкту: не запускає чужий legacy ingest/warmup. Generic cron handler сумісний як запасний шлях. На Vercel worker робить HMAC-підписане продовження через `/api/studio/continue`: ключ виведений із server-only service-role key і ніколи не надсилається; timestamp/token перевіряються, URL береться з поточного Vercel production host (не з клієнтського Host). Це дозволяє продовжувати багатокрокову роботу після закриття вкладки без нового планового тарифу. Якщо self-call/хост недоступні, job залишається в БД, його може продовжити poll сторінки або чинний cron. Платні виклики не повторюються сліпо після невизначеного завершення.

Create має стабільний request UUID, insert-only і family-scoped dedupe. Оновлення — CAS по revision; running token змінюється при паузі/повторі. Пауза зупиняє наступні кроки, але не гарантує скасування вже оплачуваного HTTP-запиту; резерв такого виклику зберігається. Достовірно неоплачувана відмова до звернення до провайдера (configuration/global budget) повертає резерв. Невалідний отриманий результат враховується як відомий cost і не стає готовим матеріалом. Резерв не є додатковим списанням і не є рахунком постачальника. Cap підготовки не включає майбутню озвучку/розмови дитини: вони йдуть через наявний загальний бюджет.

Публікація пише V3 package з namespace studio.UUID, нові теми й реальні media; спочатку status=needs_review, тільки після завершення й перевірки всіх файлів — active. Новий окремий курс активується; чинний предмет/курс зберігає рішення тата щодо active/group. Прямі reader/text/voice запити до staged/withdrawn Studio уроків блокуються; невидимі курси й групи не обходяться. Повтор publish відновлює незавершене збереження по тих самих IDs. Перемикання кількох таблиць не є однією SQL-транзакцією: при збої фінального підтвердження потрібний retry, контент до цього вже позитивно рецензований і явно погоджений татом. Новий базовий link повторно перевіряється перед публікацією. Withdraw не видаляє матеріали чи прогрес; новий окремий курс також ховається, старий предмет не вимикається.

Public child links вибирають із jobs лише whitelist metadata — не source snapshots, unit questions/keys чи model prompts. Контент/квізи/голос після publish — той самий V3 reader і наявні механізми. Published проєкт не перегенеровується поверх збереженого прогресу. Зараз немає фотогенерації, відеогенерації, автоматичного виконання Roblox-коду чи генерації повного річного підручника одним натисканням. Перший зріз свідомо обмежений повним уроком/мінікурсом до шести уроків.

[Педагогічна перевірка](../pedagogy-reviews/2026-11-11-studio-manifest.md). Реальний API/приватний production DB не тестувалися цим агентом; конкретна якість першого живого курсу оцінюється до його публікації. Живі платні API й приватна production-база в цій сесії не перевірялися; runtime використовує уже налаштований OPENAI_API_KEY застосунку. SQL-міграція та нові підписки не потрібні.


Додаткова фінальна перевірка: типізований текст схем присутній у display-контексті репетитора й підписі preview; дизайнер не отримує приватні відповіді квізів. Перевірений route/rates передаються безпосередньо в router для всього виклику, щоб кеш маршруту не змінював уже зарезервовану ціну/провайдера. Клас зберігається лише як внутрішня сумісність контракту; для позашкільних курсів UI питає вік, а не шкільний клас.
