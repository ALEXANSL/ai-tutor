# Узгоджений контракт озвучення й повторна рецензія

Регресія від 2026-11-17: автор за контрактом повертає narration=null для звичайних українських блоків; validateStudioLesson перетворює це на повний runtime-сценарій. Той самий збережений об’єкт потрапляє рецензенту зі спільною інструкцією author-null. Рецензент вимагає повернути null, сервер знову матеріалізує текст. Повторення непродуктивне й витрачає кошти.

Вихідний model-view candidate використовує той самий контракт, що author schema: uk non-code narration=null, code/en/de мають авторський сценарій. Runtime-сценарій лишається повним у збережених уроках/публікації. Проєкція не мутує їх. Спільні інструкції чітко розрізняють ці дві форми; рецензент перевіряє повноту навчального text і словесних пояснень, authored narration для code/native, але не видає null projection за перевірений реальний звук. Старі feedback не є доказом помилки й не мають переважати актуальний контракт.

Додати явну повторну рецензію готового чернеткового уроку без авторства/дизайну: доступна для failed/paused/needs_changes із наявним уроком і погодженим планом, за винятком незавершеної публікації. Вердикт незалежний; pass дозволяє лише батьківський перегляд/публікацію, непрохідний вердикт показує зауваження без запуску прихованих виправлень. Для багатоурочного курсу перевірка не запускає інші уроки. Повтор після збою зберігає режим review-only; звичайні авторські цикли лишаються автоматичними. Чинна дитяча версія й доступ не змінюються.

STUDIO-CAP має показати резерв наступного етапу й доступний залишок. Резерв невизначеного старого запиту не видаляємо: скриншот не доводить, чи обробив його провайдер.
