# Єдина школа → план навчання й домашні завдання

## Що підтверджено 2026-11-11

Перевірено публічні сторінки https://eschool-ua.com/parents та https://eschool-ua.com/documents/oferta. Офіційний опис містить розклад, домашні завдання та дані дитини; угода — PDF «Договір (публічна оферта) №2» від 28.08.2025. Окремої публічної специфікації стороннього API на перевірених сторінках не виявлено. Це не доказ відсутності API і не підтвердження дозволу на будь-яку автоматизацію. Публічні умови вимагають правомірного користування; пункт 6.3.4 прямо вимагає не передавати облікові дані третім особам; пункт 7.4 відносить ризики доступу третіх осіб із логіном/паролем до користувача. Авторизований вебкабінет власника не відкривався, запити щоденника/refresh/session не досліджувались.

Відповідь Google технічно правдоподібна, але URL /api/v1/diary/lesson/... є прикладом, наявність JSON та refresh_token — припущеннями, «менше двох секунд» не підтверджено. Внутрішній API все одно є API; використання звичайної власної сесії не означає обходу авторизації. CAPTCHA/MFA проходить власник звичайним способом, доступи інших дітей/класу не збираються.

## Рекомендований шлях

1. Отримати точне посилання на щоденник від власника (без пароля/токенів у чаті). Увійти звичайним способом у керований браузер або дослідити мережеву взаємодію з його участю. Перевірити теми, ДЗ, дати здачі, ідентифікатори уроків/предметів/дитини, вкладення, пагінацію, часовий пояс, термін сесії й дозволений спосіб доступу.
2. Спочатку синхронізація читання одним натисканням через локальний browser companion/розширення в уже авторизованому кабінеті. Сесія/пароль лишаються на пристрої власника; у репетитор передаються нормалізовані завдання, не cookies, токени чи весь щоденник. Канал приймання репетитора теж автентифікований і прив’язаний до family/child. Це варіант архітектури, ще не реалізоване розширення.
3. Серверна синхронізація за розкладом — лише після підтвердження підтримуваного входу/оновлення сесії. Секрети у сховищі з шифруванням, статуси «підключено/потрібен вхід/помилка», кероване відключення. Не обіцяти постійний доступ на основі скопійованого короткоживучого токена.
4. Запасний шлях: ручний текст/скриншот, незалежний від нестабільного вебінтерфейсу.

## Модель даних і інтеграція

Окремий school assignment: family, child, provider, external id, external child id, subject, lesson date, due date, topic, assignment text, attachment descriptors, source updated time, last synced time. Unique (family, child, provider, external id); повторний імпорт оновлює джерело без дублювання. Хеш/знімок дозволяє показати «вчитель змінив завдання»; видалене зовнішнє завдання архівується, виконана власна робота не стирається. Вкладення скачуються тільки з перевірених адрес і за чинним доступом, без пересилання cookies довільним URL.

Стан ДЗ: нове → у роботі → підготовлено → перевірено дитиною/татом → виконано. Згенерований файл сам по собі НЕ означає виконане/здане завдання; автоматично в школу нічого не відправляється. Прив’язка до наявного домашнього workspace через assignment id. ШІ допомагає співставити тему з завантаженими уроками; неоднозначний збіг підтверджується, матеріали не генеруються платно внаслідок кожної синхронізації.

План: «На сьогодні», «Незабаром», «Прострочені», можливість відкрити базовий урок/підготувати розширення/виконати ДЗ. Нагадування за реальним due date, без дублів і на основі часу останньої синхронізації; повідомлення про застарілі дані. Не трактувати дату уроку як термін здачі, якщо сервіс його не надав. Поточні homework записи/скриншоти й нові готові роботи необхідно інтегрувати явно, не змішувати їхні статуси.

## Що блокує живий конектор

Немає точної адреси кабінету та авторизованої сесії. Потрібні реальні відповіді сервісу, щоб визначити endpoints і формат; не писати фіктивний парсер за припущеннями Google. Логін/пароль у коді, git, чаті або промптах ШІ не зберігати. Схеми/код конектора, cron та нагадування в цьому релізі не впроваджені.

## Уточнення після отримання точного URL

Власник надав https://diary.eschool-ua.com/. Публічна сторінка має title «Eschool Щоденник», клієнтський bundle `/assets/index-Cf-GlIfj.js` (перевірений 2026-11-11). Це нові підтверджені дані, які замінюють попередню невизначеність щодо адреси.

У публічному JS є same-origin клієнти з prefix `/api`, `/api2`, `/notify`, `/fs`, credentials:include, перенаправлення SSO до https://eschool-ua.com/login, відновлення через `/api/auth/refresh` та `/api/v1/seplogin`. Це докази cookie/session механізму; окремий bearer refresh_token для стороннього cron не підтверджений. Реальна тривалість cookie, MFA й стабільність відновлення без інтерактивного входу не тестувалися.

Знайдені read-клієнти `v1/{schoolId}/SchoolBoy/{schoolboyId}/Appointment`, `v1/{schoolId}/Homework/{homeworkId}`, `v1/{schoolId}/Topic/{topicId}/File`, а також навчальні роки/періоди. Це шляхи з публічного клієнтського коду, не вигадані URL. Результати авторизованих відповідей не читались і не підтверджені. У bundle є також операції здачі/зміни відповідей — їх інтеграція не повинна викликати: погоджений напрям — read-only щоденник, без автоматичної здачі ДЗ у школу.

Блокер тепер точніший: URL уже є; для наступного кроку потрібна авторизована сесія самого власника, щоб перевірити контракт даних/вибір дитини/час життя сесії. Комп’ютерні інструменти shared desktop у поточному наборі tools відсутні; входу в браузер і запиту пароля в чат не було. Не пропонувати надсилати неочищений HAR/cURL: вони містять cookies і персональні дані. Підготовка local companion зі входом на пристрої власника лишається придатним наступним варіантом.
