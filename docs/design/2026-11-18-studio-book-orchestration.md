# Автоматична підготовка курсу з усієї книги

Власник задає предмет/матеріал, мету, кількість і тривалість уроків. Фабрика спочатку семантично знаходить підготовлені базові уроки, читає фактичний текст і перевіряє достатність; нові пояснення й приклади додає зі знань ШІ. До розпізнаних chunks книги звертається тільки за відсутності потрібної основи; OCR повторно не викликає. Загальний нейтральний огляд незмінного snapshot кешується за версією системних інструкцій; тематичні нотатки конкретного уроку не переносяться між різними контекстами. Назви, смислові межі, підбір джерел і послідовність визначає Майстерня. Діапазон є необов’язковим уточненням загального джерела, а не ручним розбиттям уроків; межу31сторінка прибираємо. Межі технічних пакетів не є межами уроків.

Explicit матеріал читається повністю keyset-пагінацією в ordinal order, з перевіркою завершеної індексації й незмінного revision stamp до/після. Жодного search8 fallback. Невеликі джерела залишаються прямим контекстом; великі — immutable scoped source-parts у jobs. Завеликий chunk ділиться losslessly, сторінки/ID зберігаються. Оригінал книги лишається на власному Drive, це backing розпізнаного тексту чинного проєкту.

Durable аналіз кожної частини → компактний загальний огляд (ієрархічне зведення за потреби) → план курсу з sourceIds та явними винятками → автоматичний контекст конкретного уроку → автор/дизайн/рецензія. Малий контекст уроку включає оригінальні уривки; завеликий проходить окрему focused підготовку всіх призначених частин та зведення, без мовчазного обрізання. Дослівні уривки у нотатках звіряються з вхідними текстами. Конспект чітко відрізняється від оригіналу, не видається за повний текст твору. План зіставляє кожну частину огляду з уроком або явним обґрунтованим винятком, але технічне покриття не замінює педагогічну перевірку тем. Не можна обіцяти будь-яку глибину цілої книги за10×20хв: потрібні чесні limitations без самовільного додавання уроків.

Кожний paid крок використовує чинні reservation/CAS/token/checkpoint/family budget. Snapshot і вже оплачені результати зберігаються при паузі, перезавантаженні, іншому паралельному проєкті; retry не перечитує тихо змінену книгу. Parent API повертає невеликий прогрес і назви джерел, не весь corpus і refs. Дорослий переглядає автоматично складений план та кінцевий результат; публікація окрема. Старі уроки/стани сумісні. Немає нових SQL migrations/сервісів; витрати на аналіз книги чесно включені у проєктний cap, який не підвищується автоматично.

Налаштування форми зберігаються окремим editable studio.form_draft без джерельного/модельного запуску. Допускаються неповні поля й ще неготові матеріали. Запуск — явна дія з повною валідацією, CAS/fenced lease й детермінованим id проєкту. Помилка запуску не видаляє чернетку й не створює дублікати. Батьківський список містить незапущені чернетки; форма має family/context-scoped локальне відновлення та flush при виході/перемиканні. Оригінальні файли без upload не зберігаються як browser File; зберігаються посилання на вже завантажені матеріали.
