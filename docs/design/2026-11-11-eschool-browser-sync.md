# Пробна інтеграція Єдиної школи через браузер

Мета: власник входить у diary.eschool-ua.com звичайним способом, читає тиждень власного щоденника й підтверджує імпорт у репетитор. Не просити пароль/cookies/HAR у чаті. Інструменти companion у поточній сесії відсутні, selected page=null; замість удаваної авторизації готується завантажуваний локальний помічник Chrome/Edge.

## Перший робочий зріз

- Manifest V3, мінімальні activeTab/scripting/storage дозволи, точні домени diary.eschool-ua.com та production репетитора. Scripting MAIN world виконує тільки GET до same-origin allowlisted read routes через наявну сесію. Пароль/cookies/токени не читаються та не експортуються. Зовнішні redirects заборонені; зміна профілю/оновлення сесії/здача ДЗ не викликаються програмно.
- З public client підтверджені /api/profile, /api/v1/seplogin, /api/v1/{school}/SchoolBoy/{pupil}/Appointment?start&end&embed=Topic,TargetHomework&fileRole=schoolboy та /api/v1/{school}/Homework/{id}. Контракт встановлений за клієнтським кодом, не за живою сесією. Helper перевіряє активний pupil binding і структуру відповіді; при зміні/відсутності прав повертає зрозумілий код, не підбирає чужі IDs.
- Дані тільки одного активного профілю учня, діапазон до 14 днів, обмежена паралельність/час. Нормалізація: предмет, дата уроку, тема, текст ДЗ, явна TargetAppointmentDate як термін, кількість вкладень. Імена, оцінки, інші діти, contacts, cookies, attachment URLs не передаються. Вкладення відкриваються в оригінальному щоденнику.
- Пакет у chrome.storage.session до 15 хв; передавання через content-script на точному production origin, nonce/source/origin checks. Резервно — нормалізований JSON без секретів. Батьківська сторінка перевіряє схему, показує preview й вимагає явного імпорту. Пакет зберігається тільки після цього.
- Parent-only імпорт з прив’язкою до внутрішнього child. Ідентифікатори власника/дитини беруться з сесії. Jobs documents окремих типів: connection і entry; deterministic UUIDs, CAS, idempotent packet id, захист від застарілої синхронізації. Повторне оновлення зберігає користувацький статус та зв’язок з домашньою роботою. Частковий імпорт може повторюватись; відсутні записи автоматично не видаляються.
- Предмети зіставляються за точною нормалізованою назвою; батько може вибрати інший предмет/урок вручну. Немає платної генерації при синхронізації. Дитячий щоденник показує домашні завдання, явні терміни й статуси; нагадування всередині застосунку. Згенерований файл не означає здане ДЗ. Ніяких автоматичних повідомлень учителям чи запису в школу.
- Переходи до наявного уроку/предмета й заповнення запиту в домашньому workspace з реальним текстом завдання. Доступ до source entry перевіряється сервером.

## Межі першого тесту

Потрібно один раз завантажити ZIP, розпакувати й додати як unpacked extension в Chrome/Edge. Це не опубліковане розширення Chrome Store; платної підписки немає. Браузерний помічник запускається власником, автоматичного server cron немає. Після expiry потрібно знову відкрити щоденник звичайним способом. Технічне підключення підтверджується тільки після успішного читання реального акаунта; тестові API не видаються за живі дані.

## Уточнення пристрою: Android Chrome

Власник повідомив про корпоративні обмеження на комп’ютері й успішний вхід через Chrome на телефоні. Chrome Android не підтримує desktop extensions. Основний варіант тепер — повністю автономна JavaScript-закладка, яку батько зберігає у власному Chrome та запускає на вже відкритому diary.eschool-ua.com. Зовнішні scripts не підвантажуються, eval немає. Відкривається ізольований Shadow DOM із вибором дат, читанням і копіюванням нормалізованого пакета. Вставлення в репетитор і підтвердження імпорту виконуються явно. Текст URL закладки ~24 КБ, збирається з того самого read-only collector під час prebuild. Для Android використовується запуск через підказку збереженої закладки в адресному рядку. Без зміни корпоративних політик, DevTools, пароля або скопійованих токенів.

Спосіб запущений через справжній javascript: URL у Chromium з mobile emulation та mocked school responses. Установка закладки в реальному Android Chrome і фактична сесія користувача — наступна жива перевірка, не оголошена успішною наперед. Офіційний native app для цього сценарію не використовується.

## QA / межі

Unit перевіряють тільки GET і активний pupil binding, відмову на 401/teacher profile, відсутність names/grades/file URLs у пакеті, idempotency/CAS, isolation, збереження done при зміні умови, правила parent/child, dates і прив’язку до справжнього уроку. Browser: 320/390/768/1440 × light/dark, точний bookmarklet → clipboard → реальний SchoolImport preview → mocked import action. Не було live paid AI або записів у школу. Chrome цього середовища заборонив unpacked extensions через administrator policy; прапорці/політики не змінювалися. Desktop packaging та логіка перевірені, фактична установка desktop extension тут не підтверджена. Mobile bookmarklet не потребує extensions.

Наявні записи зберігаються при відключенні; первинне зіставлення предмета — тільки за точною нормалізованою назвою. Конкретний урок батько обирає явно. Шкільне завдання додається в початковий запит homework workspace й актуалізується сервером при продовженні роботи; автоматичної AI-генерації під час синхронізації немає. In-app reminders на головній/у щоденнику, ручні статуси; server cron та push/e-mail не додавались. Відсутні записи автоматично не видаляються, щоб неповна відповідь школи не стирала історію.
