# Autonomous review and independent Studio projects

The current review worker explicitly sets needs_changes for every non-pass verdict. Replace that manual gate with automatic author/design → review cycles, retaining exact candidates, structured corrections, original parent instructions and per-project budget reservations. Visual-only fixes go directly to the designer. Continue until pass; retain parent approval of the plan and final publication. Do not introduce a two-round limit. Stop with a visible reason on exhausted budget, uncertain paid failure, explicit parent pause, or an identical failed candidate/correction fingerprint after a repair. Never silently increase a cap or publish rejected material.

Persist immutable family/project/lesson-scoped review events in done jobs, with round, timestamp, verdict, corrections and routed next stage. The project unit keeps only small round/fingerprint state; no growing full history in large course headers. Parent can browse review history while generation continues. Legacy needs_changes projects without an explicit automation stop resume on polling/workspace wake, preserving manually paused/failed/published states.

Each project retains its own project ID, generation token, job lease and revision CAS. Test two distinct project jobs with overlapping model promises, and duplicate workers for one job. A generic jobs tick that requeues a Studio step must schedule its dedicated continuation; otherwise leaving that project's page can strand it while other work consumes the generic worker's time. Catalog heartbeat wakes queued projects independently and refreshes saved status, without starting a second paid call for a running lease. Continuation POST retries are safe only because claims and project tokens deduplicate them.

Additional user request: audit the homework generation contract and DOCX/PPTX exports. Deliverable quality must include substantive explanations, coherent task-specific structure, meaningful visuals/tables/diagrams and explicit source/asset limitations. A successfully created file is not itself evidence of acceptable educational content. Preserve existing child text/voice interaction and file access controls; do not spend on external image APIs without the existing explicit generation authorization/budget path.

## Implemented and checked

Review metadata stays small in each unit; immutable review_event documents carry full structured corrections with paginated family/project-scoped reads. Explicit parent instructions persist across cycles, including legacy editor notes. Two concurrently suspended provider promises prove prompt, output and cost isolation. Generic worker requeues trigger a dedicated wake; repeated continuation POSTs are protected by project token and existing CAS/leases.

Homework authoring uses a separate bounded OpenAI route so richer files do not slow or reconfigure live chat. New structured responses include editable tables, five kinds of semantic diagram, speaker notes and explicit unresolved requirements. Technical quality checks preserve short/text-only requests; missing requested photos/maps remain draft. Browser and Office exports share visual data. PNG labels use bundled, licensed DejaVu outlines to avoid host-font dependence. Native Office tables and media are inspected in produced packages; a real Office-app rendering remains unverified in this environment.
