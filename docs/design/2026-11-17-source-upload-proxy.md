# Завантаження джерел через same-origin chunks

Скарга: PPTX ~1.4 MB не доходить до обробки; UI показує сирий `Failed to fetch`. Наявний шлях передає файл браузер→Google resumable session; повторення перевіряє стан session через cross-origin fetch без локалізації transport error. Це залежить від CORS/мережі браузера. Із самого скриншота неможливо довести конкретний мережевий збій; підтверджено в коді, що саме цей шлях і помилка не захищені. Наданий PPTX окремо перевіряється extraction engine без платного ШІ.

Новий шлях: init metadata → сімейний source.upload_session у jobs (не виконується чергою, status=done), приватний Drive session URL → локальний uploadId. Браузер надсилає PUT chunks ≤1 MiB на наш origin; сервер пересилає їх у збережену сесію Google. Це нижче 4.5 MB platform body limit; загальний ліміт 50 MB збережений. GET перевіряє підтверджений Drive offset/готовий file ID. Після помилки продовжуємо ту саму сесію; завершений Drive file ID кешується, завершення імпорту лишається ідемпотентним. Не створюємо нову копію на retry.

Безпека: parent guard на кожному запиті; family scope для session UUID; 24h expiry; дозволені лише точні HTTPS Google Drive upload hosts без credentials/port, збережений URL не походить з chunk-запиту; bounded stream read; range/total/body length звіряються зі збереженим розміром; redirect=manual. Немає нової міграції чи обходу авторизації. Legacy sessionUrl лишається для старого клієнта, новий отримує й обирає proxy URL. Книги/курси/матеріали переходять на спільний upload helper. Network/auth/expired/partial errors мають зрозумілий текст; ім’я файла видно під час retry.
