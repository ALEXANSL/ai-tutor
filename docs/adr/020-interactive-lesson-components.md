# ADR-020. Інтерактивні компоненти уроку: ШІ генерує дані кроку, а не код; бібліотека безпечних компонентів

- **Статус:** **прийнято (рішення PO 2026-09-25)** — у MVP входить **повний мінімум**: формат + реєстр + 3 компоненти `number_line`, `drag_sort`, `step_reveal` (≈ 4–5 днів розробника); «шкала часу» для історії в MVP — варіант `drag_sort` (упорядкування подій), окремий компонент `timeline` — R2. Інтерактивні й анімовані уроки — стратегічний напрям (решта — R2)
- **Вимоги:** NFR-PLAT-4, AR-17, E-19 (бібліотека), NFR-SAFE-*, NFR-A11Y-7, NFR-COST-11
- **Пов'язані:** ADR-007 (оркестратор), ADR-014 (бібліотека уроків), ADR-017 (модульність — реєстр типів кроків), ADR-004 (маршрутизатор), ADR-016 (точки розширення)

## Контекст
Алекс хоче, щоб уроки були не лише «слайд + питання», а інтерактивні й анімовані: перетягування, числова пряма й дроби, інтерактивні схеми й карти, таймлайни, покрокові анімації пояснень, міні-вправи. Найпростіший на вигляд шлях — «хай ШІ напише HTML/JS уроку» — небезпечний (довільний код у застосунку дитини, XSS, зовнішні посилання, трекери), нестабільний (кожен урок ламається по-своєму), дорогий (код — у рази більше токенів) і погано тестується.

## Рішення

### 1. Модель генерує структуровані дані, код компонентів пишемо ми
- Крок уроку в `library_steps` отримує необов'язковий блок **`visual.component`** (колонка `visual jsonb` уже існує — **міграція схеми не потрібна**):
  ```json
  { "component": "number_line", "v": 1,
    "props": { "min": 0, "max": 2, "step": "1/4", "task": "place", "targets": ["3/4"] },
    "evaluate": { "mode": "exact", "tolerance": 0 },
    "fallback_text": "Де на прямій від 0 до 2 знаходиться 3/4?" }
  ```
- `component` — ключ із **клієнтського реєстру компонентів**; `props` — лише дані (числа, короткі тексти, ідентифікатори з нашого каталогу ресурсів). Модель **ніколи** не повертає HTML, JS, CSS, SVG-розмітку чи URL.
- Новий тип кроку **`interactive`** (поряд із `slide`/`choice`/`match`…): відповідь дитини — це об'єкт від компонента (напр., позиція на прямій, порядок карток), який оцінюється **детерміновано функцією компонента** (без ШІ); крок `slide` з `visual.component` — лише показ/анімація без оцінки.

### 2. Реєстр компонентів (одна точка підключення, ADR-017)
Кожен компонент — папка `app/src/lesson-components/<key>/`, що реєструє:

| Частина | Навіщо |
|---|---|
| `propsSchema` (Zod) + `v` (версія) | Валідація згенерованих даних; з тієї ж схеми будується JSON-схема для structured output |
| React-компонент (ледаче завантаження) | Показ на планшеті; сенсорне перетягування — готова бібліотека (`dnd-kit`), анімації — CSS / бібліотека `motion` |
| `evaluate(props, answer)` | Детермінована оцінка (працює і офлайн) |
| `describe(props, state)` | Короткий текст для голосового агента й журналу («Дитина поставила 3/4 між 1/2 і 1») — агент отримує опис, а не JSON |
| `promptDoc` | 5–10 рядків для промпту генерації: коли доречний, обмеження, приклад |
| `fallback` | Показ як звичайного питання/слайда, якщо компонент недоступний |
| `upgrade(v_old → v_new)` | Старі кроки бібліотеки працюють після зміни компонента |

- Які компоненти доступні предмету — дані: `subjects.config.allowed_components` (напр., математика: `number_line`, `drag_sort`; історія: `drag_sort` з `variant: "timeline"`). Тато/розробник вмикає без зміни коду генерації.
- Навчальні модулі (ADR-017) реєструють власні компоненти так само; ядро не знає про конкретні компоненти.

### 3. Генерація й валідація
1. `lesson_generation` отримує в промпті **лише каталог дозволених для предмета компонентів** (`promptDoc` + JSON-схема) і генерує блок через structured output (Vercel AI SDK `generateObject`, дискримінований union за `component`).
2. Сервер перевіряє: (а) Zod-схема й версія; (б) семантичні правила компонента (напр., правильна відповідь існує й досяжна, ≤ 8 карток, знаменники ≤ 12, усі `region_id` є в каталозі карт); (в) тексти в `props` — через звичайні правила безпеки контенту уроку.
3. Помилка → **одна** спроба виправлення з текстом помилки → знову помилка → крок зберігається як `fallback` (звичайне питання/слайд). Урок ніколи не «ламається».
4. Рендер: тексти — як звичайний текст React (без `dangerouslySetInnerHTML`), формули — KaTeX з `trust: false`, зображення/карти/схеми — **лише з нашого каталогу ресурсів** за ідентифікатором. CSP застосунку не послаблюється.

### 4. Бібліотека й повторне проходження
Крок із компонентом — звичайний запис `library_steps` (ADR-014): повтори, повторення й офлайн-пакети R2 використовують збережені дані без генерації; компоненти — частина коду застосунку, кешуються сервіс-воркером. «Перегенерувати» створює нову версію, як і раніше.

### 5. Голос і оркестратор
Client tool `show_step` не змінюється. Події компонента (`answer`, `hint_requested`) ідуть в оркестратор так само, як `submit_answer`; агент живого голосу отримує результат і `describe(...)`, щоб прокоментувати. Анімації пояснення синхронізуються з кешованою озвучкою за кадрами (`frames[].say` → окремі `audio_assets`), без нових сервісів.

### 6. Що закладаємо в MVP (мінімум) і що — R2

| | MVP | R2 |
|---|---|---|
| Формат | `visual.component` + `v` + `props` + `evaluate` + `fallback_text`; тип кроку `interactive` | без змін |
| Інфраструктура | реєстр, Zod-валідація, спроба виправлення + fallback, каталог у промпті, детермінована оцінка, `describe` для агента | `upgrade()` версій, візуальні тести компонентів |
| Компоненти (**прийнято PO 2026-09-25 — усі три в MVP**) | **3 базові:** `number_line` (числа, дроби, координати — математика), `drag_sort` (упорядкувати / розкласти по групах; режим `props.variant = "timeline"` — «шкала часу» для історії: картки подій з датами розставляються по порядку на горизонтальній шкалі, оцінка — за порядком; також граматика, природознавство), `step_reveal` (покрокове пояснення: 3–6 кадрів тексту/формули з підсвіченням і озвучкою кадру) | `fraction_bar`, `timeline`, `map` (власні SVG-карти України/світу з ідентифікаторами регіонів), `diagram_hotspots` (схема з каталогу + мітки), `animated_scene` (обмежений набір примітивів і дій: показати, підсвітити, перемістити), міні-ігри |

**Оцінка розробки MVP-частини (прийнятий обсяг):** інфраструктура ≈ 1,5 дня; `number_line` ≈ 1 день; `drag_sort` з варіантом `timeline` ≈ 1 день (сенсор планшета, доступність; варіант — ≈ +0,25 дня всередині оцінки); `step_reveal` ≈ 1 день → **≈ 4–5 днів розробника** (+ ≈ 0,5 дня дизайнера на вигляд компонентів). Варіант «лише формат + реєстр + `number_line`» (≈ 2,5 дня) — розглядався, **не обрано**. Кожен наступний компонент R2 — ≈ 1–2 дні (карти й схеми — плюс підготовка каталогу ресурсів).

## Вплив на вартість
- **Генерація:** каталог компонентів у промпті ≈ +1–2K вхідних токенів на блок (кешується провайдером), `props` ≈ +0,5–1K вихідних токенів на блок → ≈ **+$0,01–0,03 на блок**, ≈ **+$0,05–0,1 на новий 30-хв урок**; у «Економі» (≈ 11 нових уроків/міс) — ≈ **+$1/міс**.
- **Повтори з бібліотеки:** $0 додатково (дані збережено).
- **Оцінювання:** відповіді в інтерактивних кроках оцінюються кодом, а не `answer_evaluation` → невелика **економія** (частина LLM-оцінок зникає).
- Хостинг/сервіси: $0 (компоненти — частина застосунку, бібліотеки безкоштовні).

## Альтернативи
| Варіант | Чому ні |
|---|---|
| Модель генерує HTML/JS/SVG уроку, показ в `iframe sandbox` | Довільний код у застосунку дитини; нестабільно; складно тестувати й оцінювати відповіді; у 3–5 разів більше вихідних токенів; погано з офлайном і голосом |
| Готова платформа інтерактивів (H5P тощо) | Свій формат і редактор, важка інтеграція з оркестратором, голосом і бібліотекою; вигляд не контролює `designer` |
| Одразу широкий набір компонентів і «рушій анімацій» | Передчасне ускладнення; користь перевіряємо на 3 компонентах у MVP |
| Лише формат + `number_line` у MVP (≈ 2,5 дня) | Дешевше на ≈ 2 дні, але історія й мови лишилися б без інтерактиву до R2; PO обрав повний мінімум (2026-09-25) |
| Не робити в MVP нічого | Пізніше довелося б міняти формат кроків і перегенеровувати бібліотеку; мінімальний формат зараз коштує ≈ 1,5 дня |

## Наслідки
- Безпека: модель не може «вбудувати» в урок код, посилання чи чужі зображення; усе, що бачить дитина, — наш перевірений код + дані.
- Модульність: новий компонент = папка + рядок у `allowed_components`; генерація, оркестратор, бібліотека й голос не змінюються.
- Ризики: модель обирає компонент недоречно або генерує «правильні за схемою, але хибні по суті» дані (напр., неправильна відповідь) — семантичні перевірки компонента, fallback, «Перегенерувати» в кабінеті тата (ADR-014); продуктивність анімацій на Lenovo Yoga 11 разом з WebRTC (як AR-R19) — лише `transform`/`opacity`, «Менше руху».
