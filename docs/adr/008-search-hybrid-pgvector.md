# ADR-008. Індексація й пошук: Postgres (pgvector + повнотекстовий + trigram), гібридне ранжування

- **Статус:** запропоновано (2026-09-25)
- **Вимоги:** AR-4, US-2.2, 2.3, 2.5, 8.3, 8.4, NFR-PERF-5

## Контекст
Пошук по підручниках (сторінки) і по чатах/транскриптах з фільтрами предмет/тема/дата і за змістом («скорочення дробів» знаходить «ділимо чисельник і знаменник…»). Українська мова: у Postgres немає вбудованого українського стемера.

## Рішення
- **Витяг тексту:** PDF — `unpdf`/pdf.js посторінково; EPUB — розбір XHTML (розділ + позиція замість сторінки). Менше N символів на сторінку → статус «скан без тексту» (D-9).
- **Фрагменти** ~800 токенів з перекриттям, прив'язка до сторінки й теми.
- **Ембединги:** OpenAI `text-embedding-3-large`, `dimensions=1536`, тип `halfvec(1536)`, індекс HNSW (косинус).
- **Текстовий пошук:** `tsvector` (конфігурація `simple`) + `pg_trgm` (часткові збіги й морфологія).
- **Гібрид:** Reciprocal Rank Fusion векторного й текстового результатів в одній SQL-функції; фільтри — звичайні `WHERE`.
- Повідомлення чатів отримують ембединги у фоні (раз на хвилину пакетом). При збої ембедингів — лише текстовий пошук.
- Структура «розділ → тема → сторінки», залежності тем і тип «художній твір» — роль `indexing_structure` (Opus 5.5); ручні виправлення позначаються `manual_override` і не перезаписуються.

## Альтернативи
| Варіант | Чому ні |
|---|---|
| Окрема векторна БД (Pinecone, Qdrant) | Ще один сервіс і синхронізація; обсяг даних малий |
| Лише повнотекстовий пошук | Не знаходить за змістом (US-8.4 КП-1) |
| `text-embedding-3-small` (дешевше) | Економія копійок, гірша якість для української |
| 3072 виміри | Індекс HNSW у pgvector обмежений розміром; 1536 — достатньо за якістю, менше місця |

## Наслідки
- Разова індексація підручника ≈ $1–1,5; пошукові запити — частки цента.
- Зміна моделі ембедингів = переіндексація (задача у фоні).
