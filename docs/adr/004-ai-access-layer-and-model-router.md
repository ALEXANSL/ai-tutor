# ADR-004. Доступ до ШІ: Vercel AI SDK + власний маршрутизатор моделей з таблицею в БД

- **Статус:** запропоновано (2026-09-25)
- **Вимоги:** AR-5, AR-11, US-13.1…13.3, US-11.5, NFR-COST-4, 8, NFR-SAFE-13

## Контекст
Три текстові провайдери (Anthropic, OpenAI, Google). Потрібні: таблиця «роль → основна / резервна / ескалація / економ», яку змінює лише тато; автоматичний резерв при збої; ескалація; режим бюджету; облік вартості кожного виклику з визначенням порогів ≤ 1 хв; модерація поза бюджетом.

## Рішення
- **Vercel AI SDK** з прямими пакетами провайдерів (`@ai-sdk/anthropic`, `@ai-sdk/openai`, `@ai-sdk/google`) і **власними ключами** — єдиний інтерфейс, стрімінг, структурований вихід (Zod).
- **Маршрутизатор** — серверний модуль `router.callModel(role, input, ctx)`: читає `model_routes` (кеш 30 с), стан бюджету з `spend_months`, обирає модель, робить виклик, при помилці/таймауті/невалідній схемі — резерв, пише `ai_calls` і в тій самій транзакції збільшує `spend_months`. Алгоритм — `docs/02-architecture.md`, 6.2.
- Оркестратор (ADR-007) і маршрутизатор — **окремі** модулі: оркестратор вирішує «що», маршрутизатор — «чим і за скільки».
- Ціни — у таблиці `model_prices` (оновлюється без деплою).

## Альтернативи
| Варіант | Чому ні |
|---|---|
| Vercel AI Gateway (готові фолбеки, єдиний ключ) | Ще одна точка, де проходять дані дитини; таблиця ролей, економ-режим і облік бюджету все одно потрібні наші. Сумісно: можна ввімкнути пізніше, змінивши лише фабрику моделей |
| SDK кожного провайдера окремо | Утричі більше коду інтеграцій |
| OpenRouter та подібні агрегатори | Посередник з власними умовами даних — гірше для NFR-PRIV-1 |

## Наслідки
- Зміна моделі ролі — рядок у таблиці, без деплою (US-13.1 КП-1).
- Оцінка вартості — наша (±10–15 % від рахунків); перші 2 тижні — щоденна звірка.
