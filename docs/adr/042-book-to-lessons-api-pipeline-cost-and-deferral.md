# ADR-042. E-30 «конвеєр книга → уроки»: вартість token-based API і рекомендація відкласти

- **Статус:** прийнято (оцінка `architect`, 2026-10-13, відповідь на ВП-77, доручення D-125)
- **Вимоги:** `docs/01-requirements.md` E-30 (US-30.1…30.5), ВП-77; пов'язані ADR-032 (двопрохідний конвеєр індексації, повторно використовується для розбиття книги), ADR-022 (педагогічний конвеєр планування+рецензії, D-55 — той самий обов'язковий `lesson_review`/`content_qa` застосовується й до контенту E-30), ADR-033 (prompt caching)
- **Пов'язаний кошторис:** `docs/03-resources-and-costs.md` розд. 3.10

## Контекст

Алекс (PO) сьогодні готує книги **вручну**: веде діалог у своєму окремому, вже оплаченому проєкті ChatGPT (підписка **Plus, $20/міс, фіксована**), сам копіює 4 JSON-файли (`course.json`/`teacher.json`/`assets.json`/`task_tables.json`) у `/parent/materials`. E-30 (`product-manager`, D-125) пропонує повністю автоматизувати цей конвеєр: завантаження PDF/DOCX/EPUB → розбиття на частини (розширення ADR-032) → автогенерація промпту за `docs/07-content-import-prompt.md` → **прямий виклик ШІ через token-based API** → валідація наявним Zod-валідатором → імпорт → сповіщення.

PM свідомо **не** оцінив вартість і не обрав провайдера — це винесено як відкрите, критичне питання до `architect` (ВП-77), з прямим застереженням оркестратора: епік **не повинен** проєктуватись із припущенням, що він дешевший чи кращий за ручний процес.

## Оцінка

### Обсяг виходу
Орієнтир — уже імпортована «Зарубіжна література, 6 клас» (53 уроки, ≈ 450 завдань). Заміряно на фрагменті реального fixture-файлу (не вигадана оцінка): ≈ 9–11 тис. символів на урок у `course.json`, ≈ 1,5–2 тис. символів на запис завдання (і в `course.json`, і дзеркально — у `teacher.json`, обов'язковий для кожного завдання). Разом — **≈ 2,4 млн символів вихідного JSON на книгу** ≈ **1,0–1,2 млн вихідних токенів** (оцінка стиснення кирилиці ≈ 2–2,5 символи/токен — гірше за англійську, не перевірено на реальному виклику API, саме в цьому головна непевність оцінки).

### Обсяг входу
Текст книги (200–300 стор., розбитий по розділах/урокам — повторне використання підходу ADR-032, не весь текст одним блоком) ≈ **280 тис. вхідних токенів**, плюс повторюваний системний промпт на кожен виклик розділу (кешується — ADR-033 вже в проєкті, але дає тут лише помірний ефект, бо **вихід, не вхід, домінує вартість** — на відміну від `indexing_structure`).

### Вартість одного повного прогону (ціни з `docs/03` розд. 2.1, 2026-09-25 — звірити перед реальними витратами)

| Модель | Генерація | + обов'язкова рецензія (D-55/ADR-022) | Разом |
|---|---|---|---|
| Claude Opus 5.5 ($4/$20 за 1М) — модель, уже довірена проєктом для `lesson_generation` | $23,40 | +$5–8 | **≈ $28–32** |
| Claude Sonnet 5 ($2/$10) — дешевший, але не випробуваний для генерації педагогічного тексту | $11,70 | +$5–8 | **≈ $17–20** |
| GPT-5.6 Sol, промо ($4/$20) | $23,40 | +$5–8 | **≈ $28–32** |
| GPT-5.6 Sol, базова ($5/$30, після 21.11.2026) | $34,75 | +$5–8 | **≈ $40–45** |
| Gemini 3.1 Pro (≈$2/$12, ціна з агрегаторів — звірити) | $13,90 | +$5–8 | **≈ $19–22** |
| Gemini 3.8 Flash ($0,75/$3,75) — найдешевша, **не довірена** проєктом для педагогічного тексту | $4,39 | +$1–2 | **≈ $6–9** (ризик якості, не рекомендовано без пілоту) |

**Висновок:** один повний прогін на типову книгу 200–300 стор. — **орієнтовно $18–32** на якості моделі, якій проєкт уже довіряє педагогічний контент.

### Технічний факт: ChatGPT Plus ≠ API
Підтверджено (загальновідомий, стабільний з 2023 року поділ продуктів OpenAI, не спростовано): **ChatGPT Plus** — споживацька підписка на застосунок (фіксована ціна, веб/мобільний інтерфейс), **OpenAI API** (`platform.openai.com`) — окремий, token-based, попередньо оплачений рахунок (саме той, що проєкт уже використовує, `docs/03` розд. 1.8). Перетоку кредитів чи знижки між ними немає. Рекомендовано розробнику/Алексу звірити одним поглядом офіційну сторінку цін перед остаточним рішенням, якщо потрібне 100%-підтвердження з першоджерела.

### Порівняння вигоди
Ручний процес сьогодні коштує **$0 понад уже оплачену Plus-підписку**, незалежно від кількості книг за місяць (немає обмеження «книг на місяць», лише загальні лімітери повідомлень, яких Алекс не впирається). Автоматизація, навпаки, додає **$18–32 за КОЖНУ книгу**, лінійно й неперервно (не одноразова інженерна вартість, а стаття, що повторюється на кожен новий предмет/перевидання).

Тягар, який сьогодні реально падає на розробника — **кілька окремих SQL-запитів** для очищення старого контенту одного предмета — вже окремо й повністю закривається **E-29** ($0, вищий пріоритет цього ж пакета беклогу). E-30 економить лише кілька хвилин ручного копіювання файлів Алексом між ChatGPT і кабінетом — не SQL-тягар розробника.

## Рішення

**Не братися за E-30 зараз.** Не призначати йому номера зрізу в `docs/05-backlog.md`.

Причини:
1. Ручний процес уже працює (Алекс сам підтвердив, D-125) — немає реального затору, лише загальне побажання зручності, яке точніше адресує E-29.
2. $18–32 за книгу — реальна, повторювана грошова вартість, яка не зникає з часом і не замінюється наявною підпискою (Plus лишається потрібною окремо, якщо Алекс нею й далі користується для інших задач).
3. Вигода для розробника мала (кілька хвилин Алекса, не SQL-тягар розробника) проти суттєвого обсягу нової, ризикованої розробки (нова підтримка DOCX, розширення ADR-032 на генерацію уроків, а не лише структуру тем, обробка часткових помилок генерації, сповіщення).
4. Порівняно з іншими кандидатами того ж пакета (S42 — адмін-UI для E-29, S44 — інтерактивне пояснення) — обидва з однозначною вигодою і вартістю **$0** (детермінований UI/RPC понад наявні дані, без нових ролей ШІ) — E-30 програє за співвідношенням вигода/вартість/ризик на цьому етапі з великим відривом.

**Коли переглянути:** якщо з'явиться регулярний потік книг на місяць (не одноразові предмети) і ручне копіювання стане помітним тягарем для Алекса, або якщо перші реальні виклики (після пілоту на одному розділі) покажуть, що оцінка токенізації кирилиці чи обсягу повторних генерацій суттєво завищена проти факту.

## Альтернативи

| Варіант | Чому ні (зараз) |
|---|---|
| Запустити E-30 одразу з дешевою моделлю (Gemini 3.8 Flash, ≈ $6–9/книгу) | Модель ніде в проєкті не довірена для генерації педагогічного тексту (пояснення, критерії оцінювання) — якісний ризик для контенту дитини без пілоту |
| Гібрид: автоматизувати лише розбиття/формування промпту (US-30.1/30.2/30.3), а виклик ШІ й далі робить Алекс вручну в ChatGPT | Не усуває головне ручне зусилля (копіювання тексту й файлів) заради часткової автоматизації — сумнівна economy of effort проти E-29, яке дає більшу й однозначнішу вигоду за $0 |
| Відкласти E-30 без номера зрізу, пріоритизувати S42/S44 | **Обрано** — найкраще співвідношення вигода/вартість/ризик зараз |

## Наслідки
- E-30 лишається Should-кандидатом без номера зрізу в беклозі; `product-manager` фіксує це як закриття ВП-77 у `docs/01-requirements.md`.
- Кошторисний запис — `docs/03-resources-and-costs.md` розд. 3.10 і рядок 19 таблиці рішень (розд. 5).
- Якщо PO згодом вирішить повернутись до E-30 всупереч рекомендації — рекомендую пілот на **одному розділі** однієї книги (не весь прогін одразу) для звірки факту з оцінкою цього документа, перш ніж оцінювати обсяг розробки всього епіка.
