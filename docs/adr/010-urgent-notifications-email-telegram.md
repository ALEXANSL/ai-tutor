# ADR-010. Термінові сповіщення: Resend (e-mail) + Telegram Bot API (вебхук)

- **Статус:** запропоновано (2026-09-25)
- **Вимоги:** AR-9, US-11.7, US-12.1 КП-2, NFR-PRIV-10, NFR-PERF-11, NFR-COST-9, NFR-PLAT-5, R-12, R-13, D-26

## Контекст
Лише термінові тривожні сигнали, в обидва канали, ≤ 60 с, безкоштовно, мінімальний зміст (без цитати й нікнейму), незалежність каналів, повтори, тестова кнопка, бот відповідає лише в чат тата.

## Рішення
- **E-mail — Resend**, безкоштовний тариф (3 000/міс, 100/добу). Без власного домену Resend доставляє лише на адресу власника акаунта — Алекс реєструється адресою, куди мають приходити листи. `ALERT_EMAIL_TO`, `ALERT_EMAIL_FROM=onboarding@resend.dev`, `RESEND_API_KEY`.
- **Telegram — Bot API напряму:** бот створює Алекс через @BotFather; `TELEGRAM_BOT_TOKEN`; вебхук `/api/telegram/webhook` із заголовком `X-Telegram-Bot-Api-Secret-Token` (`TELEGRAM_WEBHOOK_SECRET`); заборона додавання в групи.
- **Прив'язка чату:** кабінет генерує одноразовий код (10 хв) → посилання `t.me/<bot>?start=<код>` → вебхук перевіряє код і тип чату «private» → **chat ID зберігається в Supabase Vault** (зашифровано; варіант, дозволений NFR-PRIV-10). Будь-які інші повідомлення бот ігнорує, команд налаштувань не приймає.
- **Доставка:** після класифікації `urgent` сервер у `after()` паралельно шле в обидва канали; результат — `outbound_deliveries`. Помилка → задача-повтор (до 3 разів за 5 хв) + подія «Не вдалося доставити через <канал>». (Should) повтор через 10 хв, якщо не переглянуто.
- **Зміст:** «ШІ-Репетитор: ТЕРМІНОВО — <категорія>. <час>, <урок / ШІ-друг>. Відкрийте кабінет: <посилання>». Без цитати, нікнейму, імені, e-mail.
- **Тестове сповіщення** з позначкою «ТЕСТ» з кабінету.

## Альтернативи
| Варіант | Чому ні |
|---|---|
| Gmail SMTP з паролем застосунку | Пароль застосунку дає доступ до всієї пошти Алекса — надто широкий секрет |
| Власний домен у Resend (≈ $10–15/рік) | Не обов'язково для MVP; можна додати пізніше без зміни коду |
| Web Push | Не обраний PO (D-26) |
| Бібліотеки-обгортки Telegram (grammY тощо) | Потрібні 2 методи API (`sendMessage`, `setWebhook`) — простіше напряму |
