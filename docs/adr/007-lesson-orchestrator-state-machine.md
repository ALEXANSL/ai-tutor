# ADR-007. Оркестратор уроку — детермінований скінченний автомат на сервері

- **Статус:** запропоновано (2026-09-25)
- **Вимоги:** E-4, E-6, E-9, E-16, US-12.2, US-6.5, NFR-RES-1, 3, NFR-SAFE-12, P-T

## Контекст
Урок — сценарій з кроками, розгалуженнями, перервами, паузами (тривога, бездіяльність, мережа, бюджет) і продовженням з того ж кроку. Бали — лише за правилами. Потрібні тестованість і передбачуваність.

## Рішення
- Оркестратор — **код, а не модель**: скінченний автомат зі станами `idle / diagnostic / lesson / practice / review / friend / break / paused / summary` (діаграма — `docs/02-architecture.md`, 5.1).
- Стан — у Postgres (`lesson_sessions`, `session_blocks`, `step_attempts`); збереження після кожного кроку; відповіді з `idempotency_key`.
- Правила розгалуження (US-6.3, 16.4, 16.5, 12.2, 6.7) — таблиця в коді, покрита автотестами (`docs/02-architecture.md`, 5.3).
- ШІ-ролі викликаються через маршрутизатор (ADR-004) з мінімальним контекстом (5.4).
- Бали — модуль `points`, модель не має інструмента нарахування.

## Альтернативи
| Варіант | Чому ні |
|---|---|
| «Агентний» підхід: модель сама керує уроком через інструменти | Непередбачувано, важко тестувати таймери й правила, ризик пропуску збереження кроку й порушення правил балів |
| Фреймворки агентів (LangGraph тощо) | Зайва залежність для детермінованого сценарію |
| Стан у клієнті | Втрата прогресу при перезапуску планшета; тато не бачить стан |

## Наслідки
- Кожне правило перевіряється юніт-тестом `qa-tester`.
- Жодних денних лімітів у логіці (P-T): таймери — лише тривалість уроку, перерва, бездіяльність.
