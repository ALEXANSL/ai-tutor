# ADR-001. Стек і хостинг: Next.js PWA + Supabase + Vercel

- **Статус:** запропоновано (2026-09-25), чекає затвердження Алекса
- **Вимоги:** AR-1, NFR-COST-5, NFR-PRIV-3, NFR-PLAT-1…3, NFR-RES-4, US-1.4

## Контекст
Один користувач-дитина на планшеті (Lenovo Yoga 11, Chrome) і тато з будь-якого пристрою. Потрібні: PWA, вхід через Google, реляційні дані + семантичний пошук, файлове сховище, серверні виклики ШІ з секретами, фонові задачі за розкладом. Бюджет на інфраструктуру — безкоштовні/дешеві тарифи, але не на шкоду якості й стійкості (NFR-COST-5).

## Рішення
- **Next.js (App Router, TypeScript)** як PWA (сервіс-воркер — Serwist), розгортання на **Vercel Hobby**, регіон функцій **fra1**.
- **Supabase** (Postgres + pgvector + pg_trgm + pg_cron + pg_net + Vault, Auth, Storage), регіон **Central EU (Frankfurt)**.
- Два проєкти Supabase: `dev` (Free, окрема організація) і `prod` (Free на розробці → **Pro $25/міс** з початку щоденного використання — за підтвердженням Алекса).
- Моноліт: увесь серверний код — у Next.js; окремих сервісів, черг і контейнерів немає.

## Альтернативи
| Варіант | Чому ні |
|---|---|
| Supabase Free назавжди (дешевше на $25) | Немає резервних копій (ризик втратити прогрес доньки), «засинає» після 7 днів без активності, 1 ГБ файлів не вміщує бібліотеку з озвучкою і медіа. P-Q: надійність важливіша |
| Vercel Pro ($20/міс) | Не потрібен: функцій до 300 с на Hobby вистачає, частий планувальник дає `pg_cron` (ADR-015) |
| Supabase Edge Functions для ШІ-логіки | Ліміт 150 с на Free, другий рантайм (Deno) — ускладнення без виграшу |
| Firebase / власний VPS | Firebase — NoSQL без зручного векторного пошуку й RLS-моделі; VPS — адміністрування, яке нікому робити |

## Наслідки
- Інфраструктура: $0 на розробці, $25/міс у продакшні.
- Hobby — лише для особистого некомерційного використання (наш випадок); при зміні характеру використання — перегляд.
- Регіони Frankfurt для Vercel і Supabase — мінімальна затримка між ними й до Києва.
