# ADR-016. Точки розширення: аватар (Фаза 2), офлайн (R2), модуль іспитів (R3), візуалізації, приватний чат

- **Статус:** запропоновано (2026-09-25; доповнено 2026-09-25 — багаторічність, відеоуроки)
- **Вимоги:** AR-17, NFR-PLAT-4, D-15, D-35, US-8.6, бриф 10

## Контекст
Після MVP: офлайн-режим, більше інтерактивності й візуалізацій, розширення бібліотеки, модуль підготовки до іспитів (до травня 2027), приватний чат, дешевший голос «ШІ-друга», аватар. Усе — без переробки уроку, голосу й моделі даних.

## Рішення (що закладається в MVP)
| Напрям | Точка розширення в MVP |
|---|---|
| Аватар | Клієнтський інтерфейс `TutorPresenter` (MVP — `AnimatedImagePresenter`: картинка + анімація за станами голосу, оновлено 2026-09-25); «слот ведучого» в макеті уроку; шина мовлення `SpeechBus` (стан, гучність, опц. таймінги); образ (ім'я, голос, аватар) у БД; `audio_assets.alignment`. Говорящий аватар (Фаза 2) — нова реалізація `RigPresenter` / `StreamingAvatarPresenter` + `AvatarProvider` з тим самим `voice_id`; оркестратор, client tools, транскрипти й облік не змінюються — **ADR-019** |
| Офлайн | Бібліотека як пакети (JSON + аудіо), черга відповідей з ідемпотентністю, еталони для локальної оцінки вибору |
| Модуль іспитів | Карта знань, граф тем, бібліотека, план дня; у R3 додається таблиця `assessments` і тип `library_items.kind='mock_test'` |
| Інтерактивні й анімовані уроки | `library_steps.visual jsonb` = `{component, v, props, evaluate, fallback_text}` + тип кроку `interactive` + реєстр безпечних компонентів; у MVP — 3 базові компоненти — **ADR-020** (оновлення 2026-09-25) |
| Розширення бібліотеки | Генерація незалежна від сесії → пакетна попередня генерація (Batch API, −50 %) — лише за рішенням Алекса |
| Приватний чат | `chats.kind='private'`, `parent_visibility='summary'` |
| Дешевший голос «ШІ-друга» | Абстракція `VoiceProvider` (сервер + клієнт) з вибором провайдера на роль |
| Інші користувачі | `app_users.role`, профіль дитини — окремою сутністю; `family_id` + RLS за сім'єю (ADR-018) |
| Нові предмети, будь-які книги, навчальні модулі (напр., «Додаткове навчання: програмування») | `subjects.config`, універсальний конвеєр індексації зі стратегіями за типом джерела, `learning_modules` + `module_code`, реєстри режимів і типів кроків — **ADR-017** (оновлення 2026-09-25) |
| Комерціалізація (можливо) | `families`, `family_id`, `owner_family_id` для контенту, інтеграції через `getFamilyIntegration()` — **ADR-018** |
| Багаторічність 6→11 клас | `academic_years`, `grade` / `curriculum_version`, щомісячний експорт даних — **ADR-021** (2026-09-25) |
| **Професійні відеоуроки (пізня фаза, ідея без зобов'язань; рішення PO 2026-09-25)** | Нічого окремо не будуємо. Використовуються вже наявні: структурований сценарій уроку (`library_steps` з текстами, кадрами `step_reveal` і `visual.component`) як «сценарій відео»; озвучка й таймінги (`audio_assets`, `alignment`); фонові задачі (`jobs`, ADR-015); маршрутизатор ролей (ADR-004). У пізній фазі додаються: роль `video_generation` у `model_routes`, серверний інтерфейс `VideoProvider`, задача `video.render(library_item_id)`, `library_items.kind='video'` + файл у бакеті бібліотеки, тип витрат `video` в обліку. Постачальник (рівня Pictory / Google Vids або власний рендер) і ціни — **не обираються**; окреме рішення Алекса з кошторисом **[$]** і перевіркою приватності (у відео — лише матеріал уроку, без даних дитини) |

## Альтернативи
Не закладати нічого заздалегідь — дешевше зараз, але аватар і офлайн вимагали б переписувати екран уроку й схему бібліотеки.

## Наслідки
- Невеликі додаткові абстракції в MVP (2 інтерфейси, 2 поля jsonb, 2 значення enum) — без впливу на вартість.
