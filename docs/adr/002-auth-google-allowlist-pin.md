# ADR-002. Автентифікація: Google через Supabase Auth, allowlist у змінних середовища, режим тата за PIN

- **Статус:** запропоновано (2026-09-25)
- **Вимоги:** AR-2, US-1.1…1.6, D-1, D-29, R-5, NFR-PRIV-8, 9, 11

## Контекст
Входять лише два Google-акаунти: тато і донька (не керується Family Link). E-mail — лише в змінних середовища. Ім'я й фото з Google-профілю не можна зберігати. Тато має керувати з планшета доньки за PIN. Потрібна перевірка реального входу доньки на S0.

## Рішення
1. **Supabase Auth, провайдер Google**, скоупи `openid email profile` (не чутливі) → OAuth-застосунок у статусі **«In production»** без перевірки Google. Режим «Testing» не використовуємо (токени з Drive-доступом спливали б за 7 днів; вхід лише для тестових користувачів).
2. **Allowlist:** `ALLOWLIST_PARENT_EMAILS`, `ALLOWLIST_CHILD_EMAILS`. Після OAuth-колбеку сервер звіряє e-mail; не в списку → вихід, видалення користувача Auth, екран «Цей акаунт не має доступу». Рядок `app_users` (роль) створює лише сервер. RLS: без рядка в `app_users` — жодних даних.
3. **Без імені й фото:** тригер `BEFORE INSERT OR UPDATE` на `auth.users` і `auth.identities` видаляє з метаданих ім'я й фото; `app_users` не має полів імені/e-mail.
4. **Режим тата на планшеті:** PIN (4–6 цифр) — хеш argon2id + сіль + `PIN_PEPPER`; перевірка на сервері; успіх → httpOnly-cookie `parent_mode` (підпис, простій 5 хв, прив'язка до пристрою). 5 невдалих спроб → блок 15 хв + подія в центрі сповіщень.
5. **Запасний «режим дитини»** (лише якщо вхід доньки неможливий): тато входить своїм акаунтом, вмикає режим дитини — дані пишуться на профіль дитини, вихід — за PIN.
6. **Чекліст перевірки S0** — `docs/02-architecture.md`, 10.1.

## Альтернативи
| Варіант | Чому ні |
|---|---|
| Auth.js (NextAuth) з власними сесіями | Більше коду й власне зберігання сесій; RLS Supabase довелося б зв'язувати вручну. Лишається запасним варіантом, якщо тригер очищення профілю конфліктуватиме з оновленнями Supabase Auth |
| Supabase Auth Hook «before user created» замість перевірки в колбеку | Можна додати пізніше як другий рубіж; для двох користувачів перевірки в колбеку + RLS достатньо |
| Окремий навчальний акаунт для доньки | Відхилено PO (D-1) |

## Наслідки
- Жодних паролів; вхід доньки — один раз на планшеті (сесія оновлюється автоматично).
- Ризик: Google може обмежити вхід для акаунта, який вважає молодшим за 13 років → запасний «режим дитини».
