# BUG-023 — `manual_exit` (BUG-020) додано в код, але не в БД-обмеження

| Поле | Значення |
|---|---|
| Статус | Open |
| Серйозність | **Critical** — будь-яка спроба виходу з уроку через нову кнопку падає з помилкою БД |
| Зріз | S3, продовження BUG-020 |
| Пов'язано з | `app/src/server/lessons/state-machine.ts` (`PauseReason`), `supabase/migrations/20260928100000_s3_lesson_orchestrator.sql`, `supabase/migrations/20261001100000_s4_safety_notifications.sql` |

## Корінна причина (підтверджено пошуком по коду й міграціях)
`state-machine.ts:10` — `PauseReason` тепер включає `"manual_exit"` (доданий у фіксі BUG-020) і `"break"` (доданий раніше, US-12.2).

У базі даних `lesson_sessions.pause_reason` має `CHECK`-обмеження:
- Спочатку (`20260928100000_s3_lesson_orchestrator.sql:93`): `check (pause_reason in ('manual_alert', 'air_alert', 'idle', 'network', 'budget_hard', 'parent_mode'))` — без `break`.
- Пізніше (`20261001100000_s4_safety_notifications.sql:30-33`) — окрема міграція, яка явно `drop constraint` + `add constraint` з доданим `'break'`.

**Для `manual_exit` такої другої міграції ніколи не було написано.** Тобто в реальній базі Алекса (`ai-tutor-dev`, яку він виконує вручну через SQL Editor) обмеження досі не знає про `manual_exit` — це підтверджено читанням файлів міграцій, не лише коду.

## Наслідок
Будь-який виклик `pauseLessonAction(sessionId, "manual_exit")` (кнопка «Вийти з уроку», щойно введена в BUG-020) впаде з помилкою порушення `CHECK`-обмеження на рівні Postgres.

## Підозра (потребує підтвердження свіжими логами Vercel — не підтверджено остаточно)
Алекс повідомив: «жоден з уроків так і не запустився», включно з уроком, який раніше вже відкривався й працював. Це ширше, ніж сама кнопка виходу — можливо, окрема, ще не діагностована причина (напр. вичерпання місячного бюджету після інтенсивного тестування сьогодні ввечері, і некоректна поведінка `fallback`-механізму BUG-011 у цьому конкретному сценарії, а не сама відсутня міграція). **Потрібні свіжі логи Vercel Runtime Logs**, щоб підтвердити чи спростувати зв'язок із цим багом, а не гадати.

## Завдання для developer
1. Терміново: нова SQL-міграція (за тим самим патерном, що `20261001100000_s4_safety_notifications.sql:30-33`) — `drop constraint` + `add constraint` з доданим `'manual_exit'` до дозволених значень `pause_reason`.
2. Дослідити (окремо, за наявності свіжих логів) чи є ще одна, ширша причина того, що ЖОДЕН урок сьогодні не стартував — не зупинятись лише на цій міграції, якщо логи покажуть іншу картину.
3. Розглянути, чи варто додати автотест/лінт-перевірку, що кожне значення `PauseReason` у TypeScript має відповідне значення в актуальному `CHECK`-обмеженні (щоб цей клас багу — розбіжність коду й БД-схеми — не повторювався).

Терміново — блокує реальне використання застосунку прямо зараз.
