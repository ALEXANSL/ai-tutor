# BUG-019 — Правильні відповіді дитини оцінюються як «Майже»

| Поле | Значення |
|---|---|
| Статус | Open |
| Серйозність | **Critical** — блокує проходження уроку навіть при правильних відповідях |
| Зріз | S3 (педагогічний конвеєр / оцінювання відповідей) |
| Пов'язано з | `submitStepAnswer` / `evaluateAnswer` в `app/src/server/lessons/orchestrator.ts` |

## Кроки відтворення
1. Відкрити урок (після фіксу BUG-017/018 урок тепер відкривається).
2. Дати відповідь на крок, яка об'єктивно правильна.
3. Система відповідає «Майже» (verdict `partial`/`almost`) замість «Правильно».

## Очікувано
Правильна відповідь (за змістом, з урахуванням допустимих варіацій формулювання/запису) має оцінюватись як `correct`, а не `partial`.

## Фактично
Алекс підтвердив: навіть очевидно правильні відповіді дитини система систематично не зараховує, пише «Майже» тощо.

## Гіпотези для розробника (потребують перевірки, не підтверджені)
- Регресія від BUG-013: фікс форсував `verdict = "partial"` для termінового safety-шляху — перевірити, чи це правило випадково не спрацьовує/не залишилось на звичайному (не safety) шляху оцінювання.
- Порівняння відповіді занадто строге (точний рядковий збіг замість семантичної/математичної еквівалентності): зайві пробіли, різний запис дробу («1/2» vs «0,5»), регістр, розділові знаки.
- Схема відповіді (`evaluate` в описі кроку) чи промпт для LLM-оцінювача повертає занижену впевненість/невірний поріг correct/partial.

## Завдання для developer (терміново — блокер основного функціоналу)
1. Відтворити на реальному прикладі (взяти конкретний крок і правильну відповідь, які Алекс використовував).
2. Знайти корінну причину (не просто підняти поріг) — окремо перевірити звичайний шлях оцінювання і safety-override з BUG-013, щоб не зламати той фікс.
3. Додати автотест, що фіксує регресію: конкретна правильна відповідь на реальний тип кроку (drag_sort/number_line/step_reveal/відкрита відповідь) має повертати `correct`.
4. Незалежна QA-перевірка перед мержем — це safety-суміжна логіка (оцінювання впливає на те, чи дитина рухається далі), тому не покладатись лише на звіт розробника.

## Рішення PO
Найвищий пріоритет зараз — це основний функціонал уроку, дитина не може нормально проходити урок.
