# BUG-047 — `content_qa` (ADR-034) completeness check false-flags extremely common, entirely valid short answers as "truncated" (стоп-слова «ні», «за», «до» тощо і числа-без-пробілу перед одиницями)

- **Серйозність:** Critical (систематична хибна помилка на дуже поширеному, легітимному типі контенту — «Так/Ні»-питання — у детермінованому гейті, що тепер виконується на КОЖНОМУ згенерованому блоці уроку для КОЖНОЇ дитини; веде до марного витрачання платного бюджету `MAX_REVISIONS` і — гірше — до реального приховування цілком якісного уроку від дитини (`needs_review`, `needsReviewReason: "technical"`) без жодної справжньої проблеми з текстом)
- **Пов'язана story / ADR:** US-6.21 (`docs/01-requirements.md`), ADR-034 (`docs/adr/034-content-fidelity-qa-gate.md`), комміт `9c2f2ba` (branch `claude/intelligent-carson-6exmc1`, ще не змержений)
- **Файли:** `app/src/server/lessons/content-qa.ts` (`UK_DANGLING_WORDS`, `looksComplete`), `KNOWN_UNIT_TOKENS`/`bug046Signature` (`looksEncodedCorrectly`)

## Факт (відтворено юніт-тестом проти реального коду з гілки)

### 1. `"Ні"` (укр. «Ні» = «No») як самостійна відповідь `choice`-варіанту хибно позначається як обірваний текст

`looksComplete("Ні", "label")` повертає `false`. Причина: рядок `"ні"` буквально включений у `UK_DANGLING_WORDS` (`content-qa.ts:57`) — список слів, на яких, за задумом, речення НЕ може легітимно закінчуватись. Це правильно для сполучника-частки «ні... ні» («ні риба, ні м'ясо») ВСЕРЕДИНІ речення, але «Ні» — це водночас **звичайне окреме слово-відповідь «Ні» на питання так/ні**, найпоширеніший можливий варіант відповіді в `choice`-кроках будь-якого предмета (математика: «чи парне число?», природознавство: «чи це ссавець?», мова: «чи це іменник?» тощо).

Відтворено напряму через `checkStepContentQa` на реалістичному, повністю правильному кроку:

```ts
const step: GeneratedStep = {
  type: "choice",
  questionUk: "Чи є 5 парним числом?",
  options: [
    { id: "yes", textUk: "Так" },
    { id: "no", textUk: "Ні" },
  ],
  correctOptionId: "no",
  explanationUk: "5 — непарне число, воно не ділиться на 2 без остачі.",
  sourceRefs: [],
};
checkStepContentQa(step, 0);
// -> [{ stepIndex: 0, field: "options[1].textUk", code: "completeness",
//      reason: "текст виглядає обірваним (закінчується на середині речення/слова/числа)" }]
```

Це саме та пара «Так»/«Ні», яку **сам розробник цього коду вже використовує** у резервному шаблоні BUG-011 (`generate.ts`, `getOrCreateFallbackBlock`, рядки з `options: [{id:"yes",textUk:"Так"},{id:"no",textUk:"Ні"}]`) — просто той конкретний виклик не проходить через `checkStepContentQa` (fallback перевіряє лише уривок-слайд, не власний choice-крок), тож сама розробка цей клас багу не спіймала на власному прикладі, хоча він у неї прямо перед очима.

**Наслідок у продакшн-конвеєрі (`pipeline.ts`):** будь-який `choice`-крок зі звичайною відповіддю «Ні» (без сполучника, окремим словом) провалює `content_qa` → синтетичний вердикт `"revise"` **без виклику платного `lesson_review`** → якщо модель знову згенерує «Так/Ні»-варіант (а це нормальний, очікуваний спосіб фразування — нічого «неправильного» в цьому немає, тож наступна ітерація майже напевно матиме ту саму «Ні») → після `MAX_REVISIONS` ітерацій блок йде в `needs_review` з `needsReviewReason: "technical"` **дитині взагалі не показується**, хоча урок був повністю коректний. Це саме напрямок регресії (b), якого просив уникнути запит на рев'ю: гейт, що мав ловити реальні дефекти, замість цього блокує/деградує ДОБРИЙ контент — і робить це систематично, не як рідкісний edge case, а на одному з найпоширеніших форматів вправ у застосунку.

Менш очевидні, але реальні того самого класу проблеми в тому самому стоп-списку `UK_DANGLING_WORDS`: `"за"` і `"до"` — обидва легітимні самостійні відповіді в граматичних вправах (наприклад, тема «прийменники», де вправа буквально просить вибрати прийменник зі списку — сама відповідь може бути одним словом «до» чи «за») чи в опитуваннях-дебатах («за»/«проти»). Не відтворено окремим тестом (менш частотний випадок, ніж «Так/Ні»), але той самий механізм, тому варто переглянути весь список одночасно з фіксом.

### 2. Число впритул до одиниці виміру без пробілу (`10см³`) хибно спрацьовує як сигнатура BUG-046

`looksEncodedCorrectly("Об'єм становить 10см³ рівно.")` повертає:
```json
{"ok":false,"reason":"слово «10см³» виглядає як пошкоджене кодування (³/¿ поруч із кириличною літерою в тому самому слові) — можливий mojibake CP1251→Latin-1 (BUG-046)"}
```
Причина: токенізація `bug046Signature` (`/[\p{L}\p{N}³¿]+/gu`) включає цифри в той самий «токен», що й одиниця виміру, тож `"10см³"` — це один токен, а `KNOWN_UNIT_TOKENS`-звірка (`content-qa.ts:137`) шукає точний збіг лише `"см³"` (без числа) — `"10см³".toLowerCase()` ніколи не збігається з жодним записом у білому списку, і Cyrillic-сусідство `³` спрацьовує → хибне відхилення.

Ризик нижчий за пункт 1 (українські підручники зазвичай пишуть число й одиницю через пробіл), але не нульовий: (a) генерація ШІ не гарантовано ставить пробіл щоразу; (b) реальний виданий текст підручника (де ADR-034 і задумано звіряти дослівність) може містити нерозривний пробіл, який після нормалізації тексту при екстракції іноді зникає (та сама категорія дефектів, що вже задокументована в D-110/BUG-046). Той самий клас баг, той самий модуль — варто виправити одночасно.

## Очікуваний результат
- `looksComplete("Ні", "label")` (і `"За"`, `"До"` в релевантному контексті) → `true` — самостійне слово-відповідь не повинно вважатись обірваним реченням.
- `checkStepContentQa` на кроці з нормальною парою «Так»/«Ні» не видає жодної помилки.
- `looksEncodedCorrectly("10см³ ...")`/аналогічні числа-впритул-до-одиниці з білого списку не повинні хибно спрацьовувати як BUG-046.

## Фактичний результат
- Кожен «Так/Ні»-варіант відповіді з текстом рівно `"Ні"` хибно провалює `content_qa` як «обірваний».
- Число, приліплене без пробілу до легітимної одиниці виміру з білого списку, хибно провалює `content_qa` як «пошкоджене кодування» (BUG-046).
- Обидва випадки споживають ітерацію `MAX_REVISIONS` на пусте місце і в найгіршому разі призводять до `needs_review`/приховування цілком коректного уроку від дитини.

## Конкретне завдання на виправлення для `developer`
1. **Прибрати `"ні"` (і переглянути `"за"`, `"до"`, можливо інші однослівні прийменники/частки з `UK_DANGLING_WORDS`) з правила «dangling word», АБО зробити правило чутливим до `kind`/довжини:** найпростіший безпечний фікс — для `kind: "label"` не застосовувати список `UK_DANGLING_WORDS` до рядка, що складається **рівно з одного слова** (весь trimmed рядок дорівнює `rawLast`) — однослівний підпис на кшталт «Ні»/«За»/«До» за визначенням не може бути «обірваним реченням» (нема попереднього контексту в тому самому полі, щоб з'ясувати, що речення триває). Для `kind: "prose"` це правило лишити як є (там односкладовий «текст» — це вже сам факт обриву). Додати юніт-тест саме на пару `["Так", "Ні"]` як `choice`-варіантів (той приклад із цього багу) — щоб регресія була неможлива непомітно.
2. **Виправити `bug046Signature`/`KNOWN_UNIT_TOKENS` звірку, щоб не залежати від точного збігу всього токена з цифрами:** або (a) токенізувати одиницю окремо від передуючих цифр (`\p{N}+` не включати в те саме «слово», що йде до перевірки білого списку — вирізати провідні цифри з токена перед звіркою з `KNOWN_UNIT_TOKENS`), або (b) розширити перевірку до "токен закінчується на один із записів білого списку" замість точного повного збігу. Додати юніт-тест на `"10см³"`/`"5км²"` (число впритул без пробілу).
3. Прогнати повний `npm run test` (900+ тестів мають лишитись зеленими) і додати регресійні тести саме для цих двох кейсів у `content-qa.test.ts` (файл уже існує й добре структурований — розширити ті самі `describe`-блоки).
4. Після фіксу — перевірити ще раз (можна доручити `qa-tester` у наступному проході) сценарій «Так/Ні choice-крок з нормальним поясненням» end-to-end через `runPedagogicalPipeline`, щоб переконатись, що він більше не породжує синтетичний `"revise"`.

## Примітка щодо решти рев'ю (для контексту, не для цього фіксу)
Усі інші перевірені пункти (маршрутизація бюджету `MAX_REVISIONS`/пропуск платного `lesson_review` при провалі `content_qa`, класифікація prose/label полів проти реальної Zod-схеми, `verbatim: true` лише на slide-кроці fallback-шаблону, ідемпотентність міграції, відсутність CHECK на `reviewer_role`, типчек/900 тестів/білд) — **пройшли перевірку без зауважень**. Єдина знайдена проблема — хибні спрацювання completeness/encoding-правил на реалістичному, частотному контенті, описана вище.
