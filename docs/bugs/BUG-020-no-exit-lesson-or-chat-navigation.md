# BUG-020 — Немає кнопки виходу з уроку/чату, лише «Назад» браузера

| Поле | Значення |
|---|---|
| Статус | **Fixed** (2026-09-26) |
| Серйозність | **Major** — погана навігація, дитина/тато змушені користуватись кнопкою браузера |
| Зріз | S3 (урок) / S? (чат зі ШІ-другом) |
| Пов'язано з | `LessonRunner.tsx`, `FriendChatScreen.tsx`, US-8.x (резюме уроку, BUG-008) |

## Кроки відтворення
1. Відкрити урок або чат зі ШІ-другом.
2. Спробувати вийти на головну сторінку («Сьогодні») — немає кнопки «Вийти»/«До «Сьогодні»» на екрані під час активного уроку чи чату (є лише на екрані-помилці `error.tsx`).
3. Єдиний спосіб вийти — кнопка «Назад» у браузері.

## Очікувано
- В уроці: явна кнопка «Вийти з уроку» (з підтвердженням, якщо це перерве проходження кроку), яка коректно зберігає прогрес (на якому кроці зупинились), щоб `resumeLessonSession`/`needsResumeReminder` (BUG-008) могли запропонувати продовжити з того самого місця при наступному вході.
- У чаті зі ШІ-другом: явна кнопка повернутись на головну сторінку.
- Вихід через браузерне «Назад» не повинен бути єдиним шляхом і не повинен губити прогрес.

## Фактично
Немає видимої кнопки виходу на жодному з екранів; навігація лише браузерна, і незрозуміло, чи коректно зберігається місце зупинки саме через явний вихід (а не аварійне закриття вкладки).

## Завдання для developer
1. Додати кнопку «Вийти з уроку» в `LessonRunner.tsx` (шапка екрана) — при натисканні зберегти поточний крок сесії (перевикористати механізм, що вже працює для BUG-008/needsResumeReminder) і перейти на «Сьогодні».
2. Додати аналогічну кнопку повернення на головну в `FriendChatScreen.tsx`.
3. Перевірити, що вихід під час активного кроку (ще не відповіли) і після відповіді — в обох випадках прогрес не губиться.
4. Автотест на збереження `resumeLessonSession` стану після явного виходу (не лише після помилки/офлайн).

## Рішення PO
Пріоритет — одразу після BUG-019 (критичний функціональний баг), оскільки це базова навігація, якою користуються щодня.

## Фікс (2026-09-26)
- **Урок (`LessonRunner.tsx`):** нова кнопка «Вийти з уроку» в шапці екрана
  (поруч зі «Тривога»), з підтвердженням («Вийти з уроку?» /
  «Так, вийти» / «Ні, продовжити урок»). При підтвердженні викликається
  той самий `pauseLessonAction`, що й для тривоги/бездіяльності/офлайну —
  лише з новою причиною паузи `manual_exit` (додано до `PauseReason` в
  `state-machine.ts`), яка нічим не відрізняється в збереженні стану:
  `current_step_id` не чіпається жодним типом паузи, тож
  `resumeLessonSession`/`needsResumeReminder` (BUG-008) продовжують уже
  проходити рівно з того самого кроку. Після паузи — перехід на `/today`.
- **Чат зі ШІ-другом (`FriendChatScreen.tsx`):** кнопка повернення на
  головну сторінку («← Сьогодні», посилання на `/today`) вже існувала в
  коді (з першого впровадження чату) — перевірено, що вона видима й
  працює; додаткових змін тут не знадобилось.
- **Автотести** (`app/src/server/lessons/orchestrator.test.ts`, опис
  `pauseLessonSession — BUG-020 (...)`): (1) `pauseLessonSession(...,
  "manual_exit")` ніколи не записує/не чіпає `current_step_id`; (2)
  `resumeLessonSession` одразу після такого виходу повертає точно той
  самий крок (без хибного нагадування — пауза була короткою, < 24 год).

**Немає** окремого фронтенд-тесту на клік по кнопці «Вийти з уроку» —
юніт-тести проекту працюють в `environment: "node"` (без DOM), а наявна
інфраструктура для клієнтських компонентів обмежується
`renderToStaticMarkup` (без симуляції подій); тому регресія на
збереження стану покрита на рівні серверного контракту
(`pauseLessonSession`/`resumeLessonSession`), який кнопка викликає
один-в-один через уже протестований `pauseLessonAction`.
