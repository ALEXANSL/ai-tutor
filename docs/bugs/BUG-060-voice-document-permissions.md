# BUG-060 — мікрофон блокувався після переходу до уроку

2026-11-11. Власник: розмова не запускається, інтерфейс підключення/паузи одразу закривається. У браузері відтворено: document /today має `Permissions-Policy: microphone=()`, Next client navigation на /literature-v3 не замінює політику документа; getUserMedia відхиляється навіть з наданим браузерним дозволом. Пряме завантаження того самого lesson URL має `microphone=(self)` і працює. /friend теж не було в allow-list. Public production headers перевірено без авторизації; приватна production-сесія та provider logs у цьому середовищі недоступні.

Рішення: одна узгоджена policy для документа застосунку: microphone=(self), камера й геолокація залишаються забороненими. Це дозволяє тільки власний origin і не дає дозволу на запис автоматично: voice/library компоненти викликають getUserMedia лише після явної дії користувача, браузерний дозвіл обов’язковий. API ownership/CSRF/lease/budget safeguards не змінюються. Клієнт розрізняє document-policy блокування та відмову користувача й пропонує оновити раніше відкритий документ, не створюючи voice lease до перевірки policy.

Перевірка: справжні Chromium MediaRecorder/AudioContext і fake microphone signal, mocked authenticated voice API та audio reply. До зміни: перехід із home й friend — policy false, 0 записаних реплік; прямий lesson — true, запис/відповідь. Після зміни: перехід з home/login/library, прямий lesson/friend; повний запис → відповідь → слухання, завершення/звільнення мікрофона. Це не перевірка живих API-ключів чи реального голосу дитини; невідомі provider failures не оголошуються виправленими без доказів.

Під час «Підключаю голос» не показуємо кнопку паузи мікрофона до фактичного відкриття запису: вона могла створювати враження вже підключеної/призупиненої розмови. Скасувати підключення можна кнопкою завершення. Чинний браузерний дозвіл не підмінюється; відмова користувача залишається окремим повідомленням.
