# BUG-015 — Прив'язка Telegram-бота не спрацьовує

| Поле | Значення |
|---|---|
| Статус | Open |
| Серйозність | **Low** (пониджено рішенням PO 2026-09-26 — e-mail через Resend уже працює й покриває US-11.7; Telegram лишається другим каналом) |
| Зріз | S4 |
| Пов'язано з | US-11.7 КП-1 (одноразовий код прив'язки), ADR-010 |

## Кроки відтворення
1. Кабінет тата → Налаштування → Термінові сповіщення → «Прив'язати Telegram».
2. Відкривається посилання `t.me/<bot>?start=<code>`.
3. На комп'ютері Алекса посилання відкрилось у веб-версії Telegram (не в застосунку) без активної сесії — надсилання `/start` нічого не робить.
4. На телефоні (Galaxy S24+) спроба теж не дала результату: за словами Алекса, кнопка «Start»/автоматична команда не спрацювала; ручне надсилання `/start <код>` теж не привело до прив'язки.
5. У кабінеті лишається «Telegram: не прив'язано».

## Очікувано
Після натискання «Start» у чаті з ботом (або ручного `/start <код>`) — вебхук `/api/telegram/webhook` приймає `parseStartCommand`, знаходить дійсний рядок у `telegram_link_codes`, шифрує `chat_id` і кабінет показує «Telegram: прив'язано».

## Фактично
Прив'язка не відбувається; з боку Алекса невідомо, чи не долетів `/start`, чи код на момент надсилання вже був протермінований (10 хв), чи вебхук не обробив запит.

## Не встигли перевірити (потрібно для діагностики)
- Чи справді Telegram надсилає POST на `/api/telegram/webhook` для цього чату (логи Vercel Functions за час спроби).
- Чи `getMe`-запит (визначення username бота для посилання `t.me/<bot>?start=`) повертає правильне ім'я бота — якщо `TELEGRAM_BOT_TOKEN` не той, посилання веде на неіснуючого/чужого бота.
- Чи не протух одноразовий код (10 хв) між натисканням «Прив'язати» в кабінеті й фактичним відкриттям Telegram (кілька спроб поспіль без оновлення коду).
- Реальний вміст `telegram_link_codes` після спроби — чи взагалі створюється рядок і чи не видаляється передчасно.

## Завдання для developer (не терміново)
1. Додати серверне логування (без токена/секрету) на кожному кроці: видача коду → вебхук отримав запит → парсинг `/start` → пошук коду в БД → результат.
2. Показати в кабінеті точнішу причину невдачі замість мовчазного «не прив'язано» (протермінований код / бот не відповідає / вебхук не викликаний).
3. Перевірити `getMe`-кеш і сам `TELEGRAM_BOT_TOKEN`, яким користувався Алекс, на відповідність боту, чий username підставляється в посилання.
4. Ручний тест наскрізно з реальним акаунтом Telegram (розробнику), а не лише моками.

## Рішення PO
E-mail через Resend уже надійно доставляє термінові сигнали — цього достатньо для продовження роботи над основним функціоналом (S1/S2/S3/S4 демо). Telegram — бажаний другий канал, повертаємось до нього пізніше.
