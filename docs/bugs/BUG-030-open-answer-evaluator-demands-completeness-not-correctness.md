# BUG-030 — Оцінювач творчих/відкритих відповідей вимагає повноти, а не правильності по суті (реальний приклад)

| Поле | Значення |
|---|---|
| Статус | Open |
| Серйозність | **Critical** — той самий клас проблеми, що BUG-019/022, але для творчих завдань з кількома очікуваними елементами; підриває довіру до репетитора |
| Зріз | S3 (оцінювання відкритих відповідей), продовження D-75 |
| Пов'язано з | `evaluateAnswer`/`OPEN_ANSWER_EVALUATION_SYSTEM_UK` в `app/src/server/lessons/orchestrator.ts` |

## Реальний приклад (скріншот від Алекса)
Завдання: «Склади свою мінітаблицю з трьох рядків: одне додатне число, одне від'ємне і 0. Біля кожного напиши, що воно означає (температура, висота над рівнем моря чи гроші/борг), і чому 0 особливий.»

Відповідь дитини:
```
- 6 грн - борг
12 С - 12 градусів тепла
0 хвилин до кінця уроку - ура дзвінок, урок закінчився
```

Відповідь системи:
> «Майже! Спробуй ще раз — Молодець, додатне і від'ємне числа з поясненнями чудові (борг і тепло)! Але про 0 хвилин ти написав лише як «дзвінок», а треба ще додати, що 0 — особливе число, бо воно не додатне і не від'ємне, це межа між ними.»

## Чому це баг (не просто ще один приклад BUG-022)
Дитина виконала завдання по суті ПРАВИЛЬНО: три числа (додатне/від'ємне/нуль), кожне з власною, творчою й коректною інтерпретацією (борг, температура, "нуль хвилин до кінця уроку" — цілком валідний приклад нуля як межі/точки відліку). Єдине, чого не вистачає, — явного метапояснення, ЧОМУ нуль особливий математично (не додатне й не від'ємне). Це один ДОДАТКОВИЙ елемент розуміння, а не помилка в тому, що дитина вже зробила.

Це прямо порушує щойно зафіксований принцип **D-75** (двоетапна оцінка: результат по суті блокує вердикт, доповнення/якість — ніколи не блокує, лише доброзичлива підказка) — але для ЦЬОГО типу завдання (творче, кілька очікуваних елементів, не проста числова відповідь) D-75, вочевидь, ще не застосовано послідовно в промпті/логіці оцінювання. Фікси BUG-021/022 додали детермінований шлях лише для "кінцевих чисел у підпунктах" — це завдання без підпунктів у форматі а)/б)/в), тому йде повністю через LLM-оцінювача, і сам системний промпт, вочевидь, все ще недостатньо м'який для випадку "правильно по суті + один пропущений необов'язковий елемент".

Алекс прямо каже: **«занадто прискіпливо»**. Пропонує конкретний, кращий тон:
> «що ти можеш додати про число 0, що він означає, і можна навіть дати варіанти відповідей замість демотивуючого — Майже»

Тобто: НЕ «Майже! Спробуй ще раз» (що звучить як провал і вимагає переробити), а щось на кшталт «Чудово! А чи можеш ще сказати, чому нуль особливий? (підказка: він не... і не...)» — похвала за зроблене + доброзичливе, необов'язкове доповнення, МОЖЛИВО з варіантами відповіді (multiple-choice) замість вимоги написати ще текст.

## Завдання для developer
1. Переглянути `OPEN_ANSWER_EVALUATION_SYSTEM_UK` — явно додати інструкцію для випадку "відповідь охоплює ОСНОВНІ очікувані елементи, але пропускає один другорядний/пояснювальний елемент": вердикт має бути `correct` (не `partial`), а пропущений елемент — подати як окрему, доброзичливу, НЕ блокуючу пропозицію «а ще можеш додати...» (за бажанням дізнатись більше, аналогічно до D-75 "Етап 2" для методу розв'язання, тепер поширено і на "повноту" відкритих творчих відповідей).
2. Розглянути, чи для завдань такого типу (кілька очікуваних елементів розуміння, не просто число) є сенс пропонувати варіанти відповіді (multiple-choice) для ДОДАТКОВОГО елемента замість вимоги дописати текст — конкретна пропозиція Алекса.
3. Додати регресійний тест саме на цей приклад (чи еквівалентний): відповідь, що покриває основні елементи завдання, але пропускає один описовий/пояснювальний нюанс → `correct` з необов'язковою доброзичливою підказкою, а не `partial`/«Майже».
4. Перевірити, що це узгоджується з рештою принципу D-75 і не послаблює evaluator там, де дитина справді дала неправильну ЧИ порожню відповідь (той самий тест на дійсно неправильну відповідь має й далі проходити).

## Рішення PO
Дослівно: «занадто прискіпливо, має звучати так: що ти можеш додати про число 0... і можна навіть дати варіанти відповідей замість демотивуючого — Майже». Пріоритет — високий, це продовження D-75/BUG-022, той самий клас проблем з довірою дитини до репетитора.
