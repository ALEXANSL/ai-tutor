# BUG-008 — Нагадування при поверненні після паузи > 24 год порахована, але ніде не показується

| Поле | Значення |
|---|---|
| Серйозність | **Major** |
| Зріз | S3 |
| Пов'язані критерії | US-6.5 КП-3 («*Given* пауза тривала понад 24 год, *When* дитина продовжує, *Then* перед кроком N пропонується коротке нагадування (1 слайд) попереднього матеріалу») |
| Статус | **Open** |

## Кроки відтворення (код-рев'ю)

1. `state-machine.ts` містить чисту функцію `needsResumeReminder(pausedAt, resumedAt,
   thresholdHours = 24)`, покриту юніт-тестом з промовистою назвою «resuming after 24h+
   needs a reminder slide (КП-3)» (`state-machine.test.ts`) — тест лише перевіряє, що
   функція повертає `true`/`false` за порогом; вона нічого не каже про реальну поведінку
   застосунку.
2. `grep -rn "needsResumeReminder" src/` показує **лише два місця**: визначення функції й
   її юніт-тест. Функція **ніде не викликається** з продакшн-коду — ні в
   `resumeLessonSession` (`orchestrator.ts`), ні в `LessonRunner`/`LessonPausedScreen`
   (`src/components/lesson/`).
3. `resumeLessonSession` (`orchestrator.ts`, рядки 343–349):
   ```ts
   export async function resumeLessonSession(familyId: string, sessionId: string): Promise<LessonStepView | null> {
     const scope = forFamily(familyId);
     await scope.update("lesson_sessions", { status: "active", pause_reason: null, resumed_at: new Date().toISOString() }).eq("id", sessionId);
     const { step } = await getLessonView(familyId, sessionId);
     return step;
   }
   ```
   — просто знімає паузу й повертає той самий крок N, **незалежно від того, скільки часу
   тривала пауза**; `paused_at`/`resumed_at` записуються в базу, але ніколи не
   порівнюються.
4. `LessonStepView`/`AnswerResult["next"]` (типи в `orchestrator.ts`) не мають жодного
   поля для «нагадування» — у поточній моделі даних немає навіть способу передати клієнту
   «покажи спершу коротке нагадування», тож це не питання одного пропущеного виклику, а
   відсутня наскрізна функціональність (сервер → тип → UI).

## Очікуваний результат
Після паузи, що тривала ≥ 24 год (`налашт.`), натискання «Продовжити» показує спершу один
короткий слайд-нагадування попереднього матеріалу, а вже потім — крок N.

## Фактичний результат
«Продовжити» завжди одразу відкриває крок N, незалежно від тривалості паузи — так само,
як і після паузи в кілька хвилин. Критерій прийняття US-6.5 КП-3 не виконується.

## Чому Major, не Critical
- Не стосується безпеки дитини чи втрати даних — прогрес і сама відповідь не губляться,
  дитина просто не бачить додаткового нагадування.
- Але це явний, промовисто названий критерій прийняття Must-історії (US-6.5), і наявність
  чистої функції з **тестом, що виглядає як позитивне підтвердження реалізації** (назва
  тесту буквально «(КП-3)»), створює хибне враження в `docs/STATUS.md`/README, що критерій
  виконано — ризик, що це «загубиться» й дійде до демо Алексу як непомічений розрив між
  задокументованим і реальним станом. Це саме та категорія помилок, яку DoD п.1 просить
  ловити («усі критерії прийняття виконано»).

## Завдання для `developer`
1. У `resumeLessonSession` порівняти `session.paused_at` з поточним часом через
   `needsResumeReminder` (функція вже існує й протестована — лишається її викликати).
2. Розширити тип, що повертає `resumeLessonSession` (і, відповідно,
   `AnswerResult["next"]`/`LessonStepView`, або окремий проміжний стан), полем на кшталт
   `{ reminderStep: { textUk: string } | null }`, і показати цей слайд у
   `LessonRunner`/`LessonPausedScreen` перед кроком N (природний джерело тексту нагадування
   — коротке резюме з `library_items`/попереднього кроку, а не новий виклик ШІ — за
   принципом «без нових витрат», якщо можливо, або дешевий кешований варіант).
3. Після фіксу — інтеграційний тест (db- або component-рівня), що явно перевіряє: сесія з
   `paused_at` > 24 год тому + `resumeLessonSession` → повертає ознаку нагадування; сесія з
   недавньою паузою → не повертає. Поточний юніт-тест чистої функції варто залишити, але
   перейменувати так, щоб не створювати враження про наскрізне покриття (напр. «pure
   helper only — see orchestrator integration test for the actual wiring»).

## Тести
Не автоматизовано на рівні продукту (функціональність відсутня); гап задокументовано
код-рев'ю вище (`needsResumeReminder` не викликається за межами свого файлу й тесту).
