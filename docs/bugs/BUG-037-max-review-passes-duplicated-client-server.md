# BUG-037 — `MAX_REVIEW_PASSES` дублюється вручну між сервером і клієнтом — ризик розсинхронізації

| Поле | Значення |
|---|---|
| Статус | Open (non-blocking, знайдено QA під час перевірки BUG-035) |
| Серйозність | Minor — «прихована бомба», не поточна поломка |
| Пов'язано з | `app/src/server/lessons/pipeline.ts`, `app/src/components/lesson/LibraryWarmProgress.tsx` |

## Опис
Фікс BUG-035 додав лічильник проходів рецензії «Перевірка X з N» на прогрес-екрані прогріву. `N` — це `MAX_REVIEW_PASSES`, визначена ДВІЧІ вручну: один раз як серверна константа в `pipeline.ts` (`MAX_REVISIONS + 1`), і ще раз як окрема клієнтська константа в `LibraryWarmProgress.tsx` (з коментарем, що її потрібно синхронізувати вручну — серверний код не можна імпортувати в клієнтський компонент).

Сьогодні обидві рівні 3, тож бага немає — але якщо колись `MAX_REVISIONS` зміниться в `pipeline.ts` без відповідної ручної правки в `LibraryWarmProgress.tsx`, дитина може побачити безглузде «Перевірка 4 з 3» чи подібне.

## Завдання для developer (не терміново)
Винести число максимальної кількості проходів рецензії у спільний, фреймворк-незалежний модуль констант, який можна імпортувати і з серверного, і з клієнтського коду (наприклад, чистий `.ts`-файл без `"server-only"` в `@/server/lessons/` чи новий `@/shared/` модуль), щоб усунути ризик розсинхронізації назавжди. Не блокує реліз BUG-034/BUG-035.
