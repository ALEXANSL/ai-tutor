| Пов'язано з | `app/tests/db/s1-materials.test.ts`, нові міграції `20261002100000_s5_lesson_nav_tts.sql`, `20261002110000_s27_library_warmup.sql` |

## Контекст
Знайдено незалежною QA-перевіркою перед мержем US-6.16/ADR-025 + ADR-023 (коміти `3f5d2a4`, `cc4215c`).

## Фактично
1. `s1-materials.test.ts` ("model routes are seeded for every new family by trigger") реально падає — захардкоджений очікуваний масив ролей не оновлювався з S3b, хоча S4 (`friend_chat`, `safety_moderator`) і тепер S5/S27 (`passive_narration`, `step_reinforcement`) додали нові seed-ролі. Підтверджено git diff — сама проблема існує щонайменше з мержу S4, не спричинена цим мержем.
2. Жодна з двох нових міграцій не отримала власного `tests/db/s*.test.ts` файлу (є для s1b/s2/s3/s3b/s4, немає s5/s27) — `presentation_mode`/`mode`-констрейнти, `ai_calls.job_id`/`get_library_warm_daily_spend`, seed `passive_narration`/`step_reinforcement` не покриті тестами проти реальної БД. Коректність підтверджено вручну через psql цього разу, але це не автоматизовано.

## Завдання для developer (не терміново, не блокує нічого)
1. Оновити `s1-materials.test.ts` — або оновити очікуваний масив ролей, або (краще) перевести перевірку на "усі очікувані ролі присутні" замість точного порівняння масиву, щоб це не ламалось знову при кожному новому зрізі.
2. Додати `tests/db/s5-nav-tts.test.ts` і `tests/db/s27-warmup.test.ts` з перевіркою нових колонок/функцій/RLS.
