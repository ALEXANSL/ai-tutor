# BUG-004 — З дитячого інтерфейсу немає виходу з акаунта; «Режим тата» без PIN мовчить

| Поле | Значення |
|---|---|
| Серйозність | **Major** |
| Зріз | S0 (виявлено на демо Алекса, виправлено в S2) |
| Пов'язані критерії | US-1.5 КП-1 («Режим тата»), US-1.2 (розмежування доступу), NFR-PLAT (спільний пристрій) |
| Статус | **Fixed** (S2, 2026-09-25) |

## Кроки відтворення
1. Донька входить своїм Google-акаунтом на спільному планшеті (Lenovo Yoga 11); PIN режиму тата ще
   не задано (типовий стан одразу після S0 — тато ще не заходив у «Налаштування»).
2. Тато бере той самий планшет, щоб зайти у свій кабінет.
3. У дитячому інтерфейсі немає жодного способу вийти з акаунта доньки: ні на «Сьогодні», ні на
   «Мій репетитор» немає пункту «Вийти».
4. Єдиний доступний вхід у кабінет тата — кнопка «Режим тата» (`ParentModeButton`) → діалог PIN.
   Якщо тато натисне «Режим тата» одразу, не знаючи, чи PIN уже задано, він бачить лише клавіатуру
   PIN без жодного пояснення; повідомлення «PIN ще не задано…» з'являється лише **після** введення
   ≥ 4 цифр і натискання ✓ (кнопка підтвердження заблокована, доки не введено мінімум символів) —
   тобто тато змушений вгадувати PIN, якого не існує, щоб дізнатися, що його не існує.
5. Оскільки задати PIN може лише сам тато зі свого акаунта (`app/src/server/auth/parent-mode.ts`,
   `setParentPin`), а увійти в кабінет інакше не можна — тато змушений відкривати анонімне
   (incognito) вікno браузера, щоб увійти своїм Google-акаунтом і задати PIN. Незручно й не
   масштабується (майбутні пристрої, скидання кешу).

## Очікуваний результат
- (а) Кнопка «Режим тата», коли PIN ще не задано, одразу (без вгадування цифр) показує зрозуміле
  пояснення: «Тато ще не задав PIN — він може зробити це у своєму кабінеті» — замість мовчазної
  невдачі чи вимоги спершу щось ввести.
- (б) У дитячому інтерфейсі є ненав'язливий пункт «Вийти з акаунта» (не на видному місці —
  наприклад, унизу «Мій репетитор»), з підтвердженням перед виходом. Вихід веде на сторінку входу
  з вибором Google-акаунта (той самий маршрут `/auth/signout`, що вже використовує кабінет тата).
- У режимі тата на планшеті (коли PIN розблоковано) також є «Вийти з акаунта» — не лише «Вийти з
  режиму тата» (яка лише повертає до дитячого екрана в тій самій сесії Google).

## Фактичний результат (до фіксу)
- `app/src/components/child/ParentModeButton.tsx` завжди відкриває клавіатуру PIN; пояснення
  «PIN ще не задано» (`uk.child.parentMode.errors.not_set`) існувало в словнику й наверталось лише
  через невдалу спробу `enterParentModeAction`, а не проактивно.
- Жодного маршруту «Вийти» в дитячому UI (`(child)/**`) не було; лише кабінет тата
  (`app/src/app/parent/layout.tsx`) мав форму `action="/auth/signout"`.

## Причина
Дитячий інтерфейс проєктувався як «вхід один раз, далі донька не виходить», тому вихід з акаунта
не закладався в S0/S1. Сценарій «той самий пристрій, тато ще не налаштував PIN» не був у
демо-чеклісті S0 і виявився лише на демо Алекса.

## Виправлення (S2)
1. `ChildLayout` передає `ParentModeButton` прапорець, чи задано PIN (`loadParentSettings` через
   `forFamily`, лише `!!pin_hash`, без самого хешу). Якщо PIN не задано, клік одразу показує
   пояснення (без клавіатури, без потреби щось вводити) з кнопкою «Зрозуміло» — `not_set`-повідомлення
   тепер проактивне.
2. Новий компонент `SignOutLink` (`app/src/components/child/SignOutLink.tsx`): непомітне
   текстове посилання «Вийти з акаунта» внизу «Мій репетитор», з інлайн-підтвердженням
   («Точно вийти?» → «Так, вийти» / «Скасувати») перед `POST /auth/signout`.
3. Кабінет тата (`parent/layout.tsx`): у режимі планшета (`via === "tablet"`) під «Вийти з режиму
   тата» додано другу кнопку «Вийти з акаунта» (той самий `/auth/signout`), щоб не залежати від
   анонімного вікна.

## Тести
- `app/src/components/child/SignOutLink.test.tsx` (`renderToStaticMarkup`): початковий стан —
  лише посилання, без форми `/auth/signout` у розмітці (не спрацьовує без підтвердження).
- `app/tests/e2e/specs/s2-child-signout.spec.ts`: анонімний відвідувач не бачить дитячого UI (вже
  покрито S0); маршрут `/auth/signout` доступний `POST`-запитом і веде на `/login`.
