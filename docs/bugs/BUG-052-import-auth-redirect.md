# BUG-052 — NEXT_REDIRECT у формі перевірки ZIP

2026-10-26. PO надіслав скриншот: після повторної перевірки початкового ZIP мистецтва показано `NEXT_REDIRECT`.

## Причина

`context()` викликає `requireParentAccess()` до читання архіву. Guard використовує Next redirect для відсутнього входу чи доступу тата (login/today/denied). Обидві server actions перехоплювали будь-який виняток і серіалізували його як звичайну помилку пакета. Обидва клієнтські catch також могли поглинути службове переривання. Це окрема проблема від підтверджених числових source_pages у PR122. Зі скриншота не можна встановити точну причину втрати доступу (таймаут, інша вкладка, вихід або інший стан входу).

## Виправлення

Через публічний `unstable_rethrow` у серверних та клієнтських catch службові переривання повертаються фреймворку перед звичайною обробкою помилок. Guard, прив’язка до сім’ї, перевірка PIN і строки сесії залишаються. Звичайні помилки пакета та повідомлення про частково завершений імпорт обробляються як раніше.

Якщо доступ завершився, користувач проходить звичайний вхід/відкриває режим тата повторно. Редирект на перевірці доступу відбувається до читання staged ZIP, створення import-lock чи будь-якого запису уроків. Сам файл із приватного staging через цей redirect не видаляється; діє попередній строк зберігання до 24 годин.

## Перевірки

20 цільових тестів server boundary та форми пройдено, TypeScript пройдено. Регресія використовує справжній Next `redirect`, а не звичайну Error з такою назвою: login/today/denied повторно кидаються обома actions з digest, без download/persist/acquire/remove. Звичайні помилки, fingerprint, повторення, часткові збої та stale responses покриті наявними тестами. Production build пройдено; lint — 0 помилок / 8 наявних попереджень; bundle scan — 100 файлів / 0 витоків за маркерами. Приватна production-сесія PO недоступна для відтворення.
