# Відео як додатковий матеріал: аудит 2026-10-23

Вимога PO: вже додані Pictory-відео з історії (§16, §17, §18–19) мають відкриватися в modal; наявні текстові уроки, порядок кроків і прогрес зберігаються.

## Підтверджені кодом дефекти

- Child subject показує відео лише всередині відфільтрованих topics. Після імпорту старі topics приховані. PR112 звузив новий вибір тем, але не відновив доступ до відео на вже прихованих topics.
- Відеокнопки взагалі немає всередині сторінок імпортованих уроків.
- Плеєр не обробляє exception server action і native media error: можливе нескінченне «завантаження». Немає захисту від запізнілого URL після close/reopen, Escape/focus trap, взаємного виключення з озвученням.
- Backend перетворює SQL/signing error на порожній список або «немає відео», маскуючи причину. Upload complete довіряє клієнтським MIME/розміру й не перевіряє наявність об’єкта.

## Виправлення

Незалежний блок усіх відеоматеріалів предмета (включно зі старими прив’язками), без повторного upload/переміщення тем. Додаткова кнопка в наявному уроці: точна прив’язка topic_id; для старих topics допускається лише унікальний точний збіг нормалізованої назви в межах того самого предмета. За неоднозначності відео залишається доступним у списку предмета, без вгадування за числами. Медіапомилки мають retry; modal зупиняє озвучення й відкидає запізнілі відповіді, закриття/навігація зупиняють відео. Відео не стає обов’язковим кроком уроку.

Збої додаткового відеокаталогу не блокують текстові уроки. Доступ до файлів — лише сім’я поточної дитини і видимий предмет/курс. Існуючі записи, файли та lesson data не переписуються.

## Межі аудиту

У середовищі немає service-role ключа production і callable Supabase/Vercel management API. Вміст трьох production записів та кодек їхніх файлів не прочитано. Доступність реального MP4 підтверджується лише авторизованим переглядом; локальні тести використовують синтетичні дані й відео.

## Доповнення: ривки відтворення та паралельний PR113

PO повідомив про 149, 25 і 35 МБ, ривки в усіх трьох файлах і гігабітний доступ. Розмір і швидкість останньої милі не доводять причину: реальні codec/container, throughput Storage, Range-відповіді та dropped frames цих production файлів тут не виміряні.

Після інтеграції PR113 збережено кілька відео на тему, signing за video ID, кнопки у LessonNavBar, додаткові зміни сортування. Стара прив’язка й усі записи доступні через незалежний список; жодної нової міграції поверх main.

Плеєр запитує native `preload=auto`, показує фактичний безперервний buffer перед поточною позицією, ціль до 60 с (або тривалість коротшого відео), допуск до 5 с — реальний Chrome може suspend перед самим порогом. Без цього допуску тест із HTTP зупинився на 58,259 с й чекав би вічно. Якщо браузер обмежив preload, є явний «Почати зараз». Під час перегляду браузер продовжує range-завантаження; waiting відображається окремим статусом. Це progressive MP4, не транскодування/адаптивний HLS і не гарантія підтримувати рівно хвилину попереду на будь-якій мережі.

App service worker більше не перехоплює video/Range/signed-video запити. Приватні файли не додаються в persistent PWA cache. Нативний browser test із фактичним SW на локальному HTTP-сервері отримав `Range: bytes=0-`, відповідь 206, 60,686 с у buffer, рух currentTime. Окремий прогін на 412/1200 px, light/dark: controls, декодування, Escape зупиняє, без overflow. Ці тести не вказують причину конкретного production збою.

## Повторний production збій після PR114

PO: ривки залишилися, початкові 60 с завантажуються надто довго; ті самі файли локально відтворюються плавно. Це не підтверджує пропускну здатність маршруту Storage → браузер або browser decode. Обов’язкове очікування хвилини погіршило UX, тому підготовка хвилинного буфера стає необов’язковою, native controls доступні одразу.

Додаємо вимірювання delivery на обраному відео: браузер і Vercel окремо запитують до 1 MiB через Range; звіт містить статус, заголовки Range, фактичні байти/час і ознаку MP4 moov-before-mdat. URL/token/cookies не потрапляють у звіт. Під час вимірювання media source від’єднується, щоб плеєр не конкурував із пробою; close/unmount так само скидають src/load, а не лише pause (pause сам по собі не зупиняє preload). Після тесту URL не запускається знову автоматично. Без прямого production доступу наступна діагностика потребує скопійованого батьком звіту.
