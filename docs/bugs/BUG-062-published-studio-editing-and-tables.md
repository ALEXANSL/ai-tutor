# BUG-062 — виправлення опублікованого уроку і справжні таблиці

Власник не міг виправити урок після позитивної рецензії й публікації. Приклад: порівняння дозволених/небезпечних публікацій відображалось одним рядком Markdown, хоча дитині потрібна таблиця.

- LessonText розпізнає безпечні Markdown-таблиці, заголовки до шести #, а також згорнуті в один рядок таблиці з валідним separator. Семантичні table/thead/tbody/th, колонки, рядки, контрастний заголовок, локальний горизонтальний scroll. HTML залишається екранованим; код і читання зі збереженням оригінальних рядків не перетворюються на таблиці. Правка відображення працює і для вже опублікованого змісту без повторної генерації.
- Published Studio проєкт приймає revise з непорожнім описом виправлень. publicationRevision означає чернетку поверх чинної публікації; автор/дизайнер/reviewer не пишуть у дитячі таблиці. Повторна публікація тепер справді викликає persist, а не лише activation старого publication.
- Той самий package namespace, ключі уроків і surviving screen/question keys; наявний importer робить upsert й зберігає UUID/прогрес. Немає видалення уроків, broad cleanup чи заміни package namespace. Старі оцінки не переоцінюються автоматично після зміни запитань.
- Посилання на розширення й повернення до базового уроку зберігаються на час правок. Повторна публікація не вмикає самостійно вимкнений татом предмет.

Перевірка: unit сценарій published → draft → review → ready → republish, UI доступність форми після публікації, стабільність ключів, links під час revision, multiline/collapsed таблиці та HTML/code escaping. Chromium: точна таблиця власника на 320/390/768/1440, світла/темна теми, 2 колонки/6 рядків без page overflow.

Межа: запис публікації залишається наявною послідовністю upsert у кілька таблиць, не SQL-транзакцією. Саме натискання повторної публікації починає оновлювати чинний матеріал; можливий збій посеред запису відновлюється повтором з тими самими ключами. Історію редакцій/rollback і транзакційну зміну версій потрібно проєктувати окремо. Приватний production-урок власника не перезаписувався під час QA.
