# BUG-039 — Дрібні прогалини в `regenerate()` для `drag_sort` і тестовому покритті ремедіації

| Поле | Значення |
|---|---|
| Статус | Open (non-blocking, знайдено QA під час перевірки US-6.15/ADR-028) |
| Серйозність | Minor |
| Пов'язано з | `app/src/lesson-components/drag_sort/index.ts`, `app/src/server/lessons/orchestrator.ts` |

## Опис (два окремі дрібні пункти)

**1. `regenerate(props, seed)` не гарантує іншого порядку.** Детермінований Fisher-Yates шафл за `seed` — коректний і відтворюваний, але для малої кількості елементів (схема дозволяє вже 2) є реальний (50% для 2 елементів) шанс повернути ТОЙ САМИЙ порядок, що й у першій спробі — тобто «повторна спроба» може виглядати пікселем-у-піксель ідентичною оригіналу. Не ламає коректність чи безпеку, лише послаблює педагогічний намір «інший приклад на те саме вміння».

**2. Немає тесту на перезавантаження посеред циклу для `open`/`interactive`.** Є лише для `choice` (`getLessonView`). Код перевірено вручну — поводиться коректно, але без автотесту.

## Завдання для developer (не терміново)
1. У `regenerateDragSort`: якщо згенерований порядок збігається з оригінальним, спробувати ще один детермінований варіант перестановки (наприклад, `seed+1`) замість того, щоб повертати no-op.
2. Додати тест на перезавантаження (`getLessonView`) посеред циклу ремедіації для `open`- і `interactive`-кроків, симетрично наявному тесту для `choice`.
