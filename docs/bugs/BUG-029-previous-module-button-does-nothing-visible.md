# BUG-029 — «Повернутись до попереднього модуля» не працює (за словами Алекса)

| Поле | Значення |
|---|---|
| Статус | Open |
| Серйозність | Major (нова навігаційна кнопка з US-6.16 виглядає непрацюючою для батька) |
| Зріз | S5 (US-6.16), щойно змержено в `main` |
| Пов'язано з | `LessonRunner.tsx` (`navPrevModule`, `PreviousModuleModal`), `orchestrator.ts` (`getPreviousModuleView`) |

## Кроки відтворення
Алекс: «повернення на попередній модуль уроку — не працює». Без деталей (немає скріншота/логу), тому нижче — аналіз коду (не підтверджено на реальному середовищі).

## Аналіз коду (зроблено оркестратором перед делегуванням)
`getPreviousModuleView` (`orchestrator.ts:749`) повертає `null`, коли `session.current_block_order <= 1` — тобто коли дитина ще на ПЕРШОМУ блоці уроку. Це очікувана поведінка (кнопка не повинна нічого показувати, якщо попереднього блоку не існує) — саме так і задокументовано в коментарі коду (US-6.16 КП-2: «`null` when this is the first block»).

**Однак клієнтський код (`LessonRunner.tsx`) не дає ЖОДНОГО видимого фідбеку в цьому випадку:**
```
{prevModule && (
  <PreviousModuleModal view={prevModule} labels={t} onClose={() => setPrevModule(null)} />
)}
```
Якщо `prevModule` лишається `null` після виклику `getPreviousModuleAction`, нічого не рендериться — кнопка виглядає так, ніби на неї взагалі не натиснули. Кнопка також ніколи не приховується/не дизейблиться заздалегідь на клієнті для першого блоку (немає client-side перевірки порядку блоку) — тобто дитина/тато завжди бачать активну кнопку, навіть коли натискання нічого не дасть.

**Це, ймовірно, і є причина скарги** — якщо Алекс тестував на першому блоці щойно відкритого уроку (найпоширеніший сценарій одразу після старту уроку), кнопка справді "нічого не робить" з його погляду, хоча технічно це "очікувана відсутність попереднього модуля", а не помилка.

**Не виключено (не перевірено)**, що є й окрема реальна помилка на другому+ блоці (де попередній модуль дійсно має існувати) — потрібна перевірка на живому багатo-блоковому уроці.

## Завдання для developer
1. **Обов'язково:** додати видимий, дружній фідбек, коли `getPreviousModuleAction` повертає `null` — напр. коротке повідомлення «Це перший блок уроку — попереднього поки немає» замість мовчазного нічого. Текст — через `uk.ts`.
2. Перевірити РЕАЛЬНИЙ сценарій (не лише читання коду): пройти урок з ≥2 блоками до кінця, натиснути кнопку на другому блоці — переконатись, що модалка дійсно відкривається з коректним вмістом першого блоку. Якщо тут теж є помилка — знайти й виправити корінну причину окремо від п.1.
3. Розглянути (не обов'язково, але бажано): приховати або дизейблити кнопку на клієнті, коли `session.current_block_order <= 1` (потрібно передавати цю інформацію в проп компонента, а не дізнаватись лише після кліку) — так дитина одразу бачить, що кнопка неактивна, замість натискання й відсутності реакції.
4. Автотест: рендер компонента з `prevModule=null` після кліку показує повідомлення «немає попереднього модуля», а не порожнечу.

## Рішення PO
Знайдено Алексом на реальному використанні щойно змерженої фічі — виправити в найближчій ітерації.
