# BUG-001 — Немає жодного чоловічого варіанту імені репетитора

| Поле | Значення |
|---|---|
| Серйозність | **Major** |
| Зріз | S0 |
| Пов'язані критерії | US-1.7 КП-2; демо-сценарій S0 (`docs/05-backlog.md`, "3 жіночих + 3 чоловічих, PM-21") |
| Статус | **Fixed** (коміт `f8d36ce`, 2026-09-25) — очікує перевірки `qa-tester` |

## Кроки відтворення
1. `SELECT tutor_name_options FROM parent_settings` (або пройти онбординг дитини й відкрити крок 2 — вибір імені репетитора).
2. Подивитись, скільки варіантів запропоновано в групі "чоловічі".

Джерело даних: `app/config/family-defaults.json`:
```json
"tutorNameOptions": {
  "f": [
    { "name": "Ліра", "hint": "тепла й терпляча" },
    { "name": "Веснянка", "hint": "енергійна й весела" },
    { "name": "Зоряна", "hint": "спокійна й уважна" }
  ],
  "m": []
}
```

## Очікуваний результат
US-1.7 КП-2: «Пропонується **3 жіночих і 3 чоловічих** імені (PM-21)». Демо-сценарій S0
у беклозі теж вимагає «ім'я репетитора зі списку (3 жіночих + 3 чоловічих)». `TutorNamePicker`
і `resolveTutorNameChoice`/`suggestedNames` вже підтримують обидві групи — бракує лише даних.

## Фактичний результат
`tutorNameOptions.m` — порожній масив. Онбордингова дитина (і тато в кабінеті) бачить лише
3 жіночих варіанти; чоловічого імені зі списку обрати неможливо (лишається тільки «своє ім'я»
з перевіркою). Порушено явний критерій прийняття US-1.7 КП-2.

Сам developer вже зафіксував це як відкрите питання в `docs/STATUS.md` («Відкрите питання до
Алекса / `designer`») — QA підтверджує, що без цього S0 не проходить DoD п.1 («усі критерії
прийняття виконано»).

## Чому не Critical
Не стосується безпеки дитини чи приватності; UI й логіка обробки обох груп повністю готові —
бракує лише контентних даних (3 імені + короткі підказки).

## Завдання для `developer`
1. Узгодити з Алексом (через оркестратора) або `product-manager`/`designer` 3 чоловічих імені-
   підказки репетитора (стиль — як у жіночих: коротке ім'я + hint 1-3 слова, напр. за аналогією
   з "Ліра — тепла й терпляча").
2. Додати їх у `app/config/family-defaults.json` → `tutorNameOptions.m` (масив із 3 об'єктів
   `{ "name": ..., "hint": ... }`), зберігаючи модульність (дані, не код — уже так реалізовано).
3. Додати юніт-тест (напр. у `app/config/family-defaults.test.ts` або розширити
   `plan.test.ts`), що перевіряє: `tutorNameOptions.f.length >= 3 && tutorNameOptions.m.length >= 3`
   — щоб регресія була неможливою.
4. Переконатися, що `AiIntro`/`getTutorGender` коректно показують «ШІ-помічник» (чоловічий рід)
   для чоловічого імені, обраного зі списку (граматичний рід у S0 визначається за голосом,
   який поки завжди `null` → `"f"`; перевірити, чи це прийнятно для S0 чи потребує окремого
   пояснення в `docs/STATUS.md`, бо голос дитина обирає лише з S12).
