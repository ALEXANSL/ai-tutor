# Маніфест майстерні: педагогічна перевірка

Дата 2026-11-11. Автор Codex, самоперевірка реалізації; це не незалежна експертиза педагога і не оцінювання реальних відповідей API.

Перевірено `app/prompts/studio.md`, системні ролі `studio.plan/author/design/review`, typed contracts і publish gate. Окрема рецензія в самому продукті — новий API-виклик із роллю рецензента, а не інша назва авторського виклику. Автор і рецензент за замовчуванням використовують ту саму модель; це не гарантує відсутності спільних помилок. Перед дитиною результат переглядає тато.

## Перевірені вимоги

- Вік/ціль/підготовка й інструменти впливають на план. Клас не потрібно вводити для позашкільного курсу: native metadata отримує поточний навчальний рік; модель орієнтується на явно заданий вік і запит.
- Урок містить пояснення, повний розібраний приклад, практику/кроки, підсумок і квізи. Одна «коротка анотація» не проходить мінімальну перевірку. Самих питань підручника недостатньо для нового матеріалу; пошук у книгах або чесне загальне пояснення доповнює базу.
- Підручник не обмежує допитливість. enrichmentNote явно відділяє загальні знання від наданих джерел. sourceIds перевіряються по фактично завантажених фрагментах. Не стверджувати, що прочитано всю книгу, виконано вебпошук чи запущено Roblox Studio.
- Історичні факти, свідчення й вірування відокремлені; тон нейтральний і поважний.
- Код показується повністю як екранований pre/code. Автоматичного виконання коду немає. Практичні приклади Roblox потребують перевірки у справжній Studio; модель не повинна називати їх виконаними.
- Для ручних робіт потрібні конкретні матеріали, розміри й порядок дій. Потенційно небезпечні операції залишаються дорослому. Рецензент перевіряє ці межі й узгодженість схем; автотести не доводять безпечність кожної майбутньої інструкції.
- Схеми — реальні SVG з обмеженими типами/полями, коректним XML-escape і без script/URL/foreignObject. Генерація фотографій чи відео сторонніми сервісами сюди не підміняється.
- Рецензент має самостійно перевірити відповіді квізів і порівняти з correctIndex автора. Pass з непорожніми issues не приймається. Revise/reject блокує publish. Human preview показує ключі тільки батькові; дитині — стандартний public quiz DTO.
- Проєкт можна призупинити/продовжити. Це не «втрачена серія», немає таймера тиску чи штрафу за перерву/тривогу. Повернення з розширення не видаляє базовий урок або його прогрес.

## Що доводять перевірки

Unit-тести доводять коректність переходів, меж джерел, розділення ключів, CAS і фінансових gate. Браузер перевіряє форми/план/preview/links на синтетичних даних. Live paid API у цій сесії не викликався. Перший реальний пробний урок потрібно оцінити по змісту до публікації: правильні приклади, зрозуміла мова, досяжна практика, відповідні ілюстрації, вікова доречність та відсутність непідтверджених тверджень.
