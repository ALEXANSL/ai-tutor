# 07 — Промпт для підготовки підручників у ЖПТ (універсальний формат імпорту)

> **Оновлено 2026-10-20.** Схема v2 ("пакет розділу" — `flow[]`, повні
> тексти творів у `readings.json`, квізи `single_choice`, ілюстрації й
> маленький PDF на кожен урок) — тепер **основний, чинний формат** для
> будь-якого НОВОГО предмета. Вона вже прийнята тричі (`ukrlit-tutor-package`
> — Українська література, `ukrmova-tutor-package` — Українська мова,
> `history-tutor-package` — Історія) і підтверджена як стандарт (ADR-044,
> ВП-78). **Промпт нижче в секції "ПРОМПТ ДЛЯ ЖПТ (чинна схема v2)" — той,
> яким готуй УСІ наступні підручники.** Старий контракт v1.0
> (`literature_v2_*`, формат без `flow[]`/`readings.json`, з відкритими
> завданнями) лишається нижче в розділі "Застаріле (v1)" — лише довідково,
> для вже імпортованої "Зарубіжної літератури", яку свідомо не переводимо на
> нову схему (D-127).

**Навіщо цей документ.** Кожен новий предмет з "повним пакетом" раніше
вимагав, щоб розробник заново вигадував схему імпорту, бо ЖПТ щоразу
повертав трохи інший формат JSON. Цей документ фіксує ОДИН постійний
контракт — промпт нижче й JSON-схему під ним — щоб той самий імпортер
(`literatureV3Import.ts` + таблиці `literature_v3_*`) міг приймати будь-який
майбутній предмет (літературу, мову, історію, правознавство, курс "Я
досліджую світ" тощо) без нової розробки щоразу. Формат маніфесту
(`package.json`) завжди називається за шаблоном `"<предмет>-tutor-package"`
(напр. `ukrlit-tutor-package`, `history-tutor-package`) — новий предмет
просто дає своє ім'я, решта контракту незмінна.

**Коли НЕ підходить цей формат.** Для предметів із задачами на кшталт
"виберіть правильну відповідь із 4 варіантів" БЕЗ повних текстів творів і
без ілюстрованих "екранів" (математика, природничі предмети з короткими
тестовими завданнями) є простіший формат — `course_v2_*`
(`mathCourseV2Import.ts`). Якщо не впевнений, який формат підходить новому
предмету — запитай розробника (мене) одним реченням перед тим, як
запускати ЖПТ.

## Як користуватись

1. Скопіюй весь текст із секції **"ПРОМПТ ДЛЯ ЖПТ (чинна схема v2)"** нижче.
2. Встав його в новий чат у своєму проєкті ЖПТ (той, де ти вже обробляєш
   книги), і ДОДАЙ після нього: назву підручника, клас, видавництво, рік, і
   сам файл підручника (PDF або фото сторінок).
3. Отримавши відповідь, перевір, що ЖПТ повернув **РІВНО 6 JSON-файлів**
   (`package.json`, `public/course.json`, `public/readings.json`,
   `private/teacher.json`, `catalog/assets.json`, `catalog/pages.json`) і
   архів ілюстрацій + маленькі PDF уроків — **без жодних Python/SQL-скриптів
   і без "інструкції з імпорту"**: та частина нам не потрібна, наш імпортер
   уже існує.
4. Завантаж усі файли мені в чат — я перевірю їх нашим існуючим валідатором
   і за потреби повідомлю, що саме ЖПТ зробив не так (тоді просто попроси
   ЖПТ виправити конкретне поле — не переробляти все заново).

## ПРОМПТ ДЛЯ ЖПТ (чинна схема v2)

```
Ти готуєш навчальний матеріал для ШІ-репетитора дитини. Результат — РІВНО
6 JSON-файлів з наведеною нижче структурою (плюс архів ілюстрацій і
маленькі PDF-файли уроків, якщо є малюнки/скани), і більше нічого (жодних
скриптів, інструкцій з імпорту, README). Увесь текст — українською, крім
ключів JSON (вони завжди англійською, як у прикладі).

Контекст: кожен "task" (завдання) — ТЕСТ З ВАРІАНТАМИ ВІДПОВІДЕЙ
(single_choice), з ОДНІЄЮ правильною відповіддю. Урок — це впорядкована
послідовність кроків `flow[]` чотирьох типів: "screen" (пояснення/питання/
ілюстрація), "biography" (біографія автора), "reading" (повний текст
уривку твору чи розповіді) і "quiz" (тестове завдання) — саме в тому
порядку, в якому дитина має їх проходити.

ОБОВ'ЯЗКОВІ ВИМОГИ ДО ЗМІСТУ (не лише до структури JSON):

1. **Квізів — багато, не один-два в кінці.** Кожен урок має містити
   ОРІЄНТОВНО 6-10 тестових завдань (кроків "quiz"), розподілених по
   всьому уроку через `flow[]` — одразу після відповідного "reading"/
   "screen", а не всі скопом наприкінці. Мало завдань = урок не
   приймається.
2. **Ілюстрації — у кожному уроці.** Шукай і додавай ілюстрації з
   підручника (`kind: "textbook_illustration"`) до КОЖНОГО уроку, не лише
   туди, де скан сторінки випадково містить малюнок. Якщо в підручнику для
   якогось уроку взагалі немає жодної ілюстрації — прямо напиши про це в
   `note`, не пропускай мовчки.
3. **Тексти творів/уривків — ПОВНІ, без скорочень.** Поле `completeness`
   у `works[]` — завжди `"full"` (не "excerpt", не "abridged"). Увесь
   текст твору чи оповідання, який школярі мають прочитати за програмою,
   іде в `readings.json` цілком, розбитий на послідовні `items[]` за
   сторінками підручника (`sequence` за порядком). НЕ скорочуй, НЕ
   переказуй своїми словами замість оригінального тексту.
4. **Максимально використовуй сам підручник.** Пояснення (`screens[].
   content`), запитання, формулювання завдань — спирайся на РЕАЛЬНИЙ текст
   і матеріали підручника (параграфи, виноски, довідкові рамки), а не на
   загальні знання з інтернету. Кожен `screen`/`reading`/`task` повинен
   мати заповнені `source_page_ids`/`asset_refs`, що вказують на конкретну
   сторінку підручника, звідки він узятий.

## ПРОМПТ ДЛЯ ЖПТ (застаріла v1, не використовувати для нових предметів)

```

JSON-файли з наведеною нижче структурою, і більше нічого (жодних
скриптів, інструкцій з імпорту, README). Увесь текст — українською,

response_type вказує формат), без окремого поля "правильний варіант".

## Нотатка для розробника (себе ж, на майбутнє)

Якщо наступний предмет через цей промпт прийде з РІВНО такою структурою —
`literatureV2Import.ts`/`literatureV2Persist.ts`/`literatureV2View.ts` і
таблиці `literature_v2_*` вже вміють його прийняти без жодної зміни коду,
лише новий `subject_id` при імпорті через той самий екран у
`/parent/materials`. Єдине, що може знадобитись: перейменувати напис
панелі імпорту з "Зарубіжна література" на щось нейтральніше (напр.
"Повний пакет (відкриті завдання)"), якщо предметів стане кілька — це
косметика, не нова схема.
